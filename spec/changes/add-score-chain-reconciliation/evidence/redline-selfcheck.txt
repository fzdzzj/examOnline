## 判读

- [1][2]：未引入 Flyway/Liquibase，`src/main/resources/db` 不存在——建表唯一入口仍是 `schema.sql`。
- [3]：集成测试零 `@Sql`，新用例用 `schema.sql` 建表 + Mapper 直插夹具，未自建任何表。
- [4]：实体 `@TableName` 表集合与 `schema.sql` 建表集合差集为空（新实体 `reconciliation_runs` /
  `reconciliation_diffs` 均在 schema.sql 有建表块，过 `comm -23`）。
- [5]：`docker/mysql` 只挂载 `master/init` 与 `slave/init` 两个初始化目录，`migrations/` 无自动执行者
  ——脚本入库 ≠ 迁移已生效，`APPLIED.md` 已如实登记「未应用（待人工应用）」。
- [6]：reconciliation 包零 Redis API 调用（对账状态全部落 DB），符合「零新 Redis 键族」。
- [7]：总分期望值只有 `ScoreService.computeSummary` 一个公式，对账经 `expectedSummaries` 复用；
  补齐写入复用同 SET 形状的 CAS（`casBackfillTotalScore`，仅多 `total_score IS NULL` 幂等护栏）。
- [9][11]：两新表均在 AUTO_INCREMENT 块内显式 `PRIMARY KEY (id)`，H2/MySQL 双兼容。
- 第 [10] 项：迁移脚本数与 `APPLIED.md` 台账行数相等等于 19（本笔脚本入库后机检无缺口）。

> 说明：[5] 的两行命中是「初始化目录」而非 `docker/mysql/migrations`，与 AGENTS 第 4 条约定的
> 自查口径一致（migrations 目录不在 compose 挂载内）。
