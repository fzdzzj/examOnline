## 实施

1. **基线自检**：门禁三项 + 后端全量，记录数字。
2. **核实后端契约**（见上 10 项），**尤其第 1 项冲突错误码与第 6 项补考最终成绩**，结论写进回报。
3. **教师批改工作台**：
   - 待批改答卷队列（分页 / 筛选）；
   - 打开一份答卷 → 逐题打分 + 评语 → 提交；
   - **冲突处理**：捕获后端版本冲突错误码 → 提示「已被他人批改」→ 刷新答卷内容 → 让教师重看后重新打分；
   - 打分输入校验（分数不超过该题满分、非负）。
4. **成绩汇总与发布**：客观 + 主观汇总预览 → 发布前预览 → 批量发布；撤回入口按后端权限渲染；动作可用性按后端状态渲染。
5. **成绩导出**：触发后端流式导出 → `blob` 下载 → 进度提示 → 失败可重试且明示原因。
6. **缺考名单**：按考试查看被标记缺考的学生（两条结束路径产生的标记都要能看到）。
7. **补考管理**：为特定学生创建补考（独立考试记录 + `parent_exam_id` + `exam_candidates` 准入范围指定）；补考列表与准入范围查看。**不做最终成绩合并展示**（见硬约定 5），界面相应位置注明「补考最终成绩合并规则后端尚未接线」。
8. **学生成绩查询**：已发布可见；复核中按后端返回隐藏（前端不判断）；未发布如实显示「未发布」而不是空白或 0 分。
9. **学生复核申请**：剩余次数与窗口状态取后端返回；申请表单（理由等按后端入参）；提交后状态可查（待处理 / 已处理）；教师处理后呈现结果与调整说明。
10. **教师复核处理**：待处理复核列表 → 查看申请 → 处理（按后端端点与入参）→ 结果对学生可见。
11. **测试**（vitest，必须有）：
    - **批改乐观锁冲突分支**：给定后端冲突错误码，断言出现「已被他人批改」提示 + 触发刷新 + **没有**显示成功；
    - 打分校验纯函数（超满分 / 负数 / 空值）；
    - 动作可用性映射：给定不同后端状态与权限返回，渲染出的按钮集合正确（含**后端未允许时绝不显示**）；
    - 成绩可见性渲染：已发布 / 复核中隐藏 / 未发布三态各自正确（**断言前端不做本地推断**，即隐藏完全由传入的后端字段驱动）；
    - 复核资格渲染：剩余次数与窗口状态来自后端字段，前端不计数；
    - 导出失败分支：明示原因且可重试；
    - 状态映射纯函数（复核状态、缺考标记来源）。
12. **端到端演示脚本**写入 `frontend/docs/post-exam-demo.md`：`交卷（阶段 22）→ 教师批改（含制造一次并发冲突）→ 汇总预览 → 发布 → 学生查询成绩 → 学生申请复核 → 教师处理复核 → 学生看到复核结果`，另加 `force-end → 缺考名单出现 → 为该学生创建补考`。每步含前置数据、操作、**期望现象**、以及**它证明了后端哪条能力**（乐观锁 / 权限 / 流式导出 / 复核限次限时 / 缺考两条路径 / 补考独立记录与准入）。**实跑并记录真实观察结果**；跑不动的明确标注「未实跑 + 原因」，**不得声称已验证**。
