# 提案：考后闭环界面（阶段 23，方向⑤）

## Why

方向⑤把 `grading`（客观自动 + 简答教师批改）、`score-management`（汇总/发布/撤回/导出）、`score-review`（复核申请限次限时、复核中隐藏成绩）、`absence-makeup`（缺考标记、补考独立记录）四个能力域的界面补齐，形成「交卷 → 批改 → 发布 → 复核 / 缺考 → 补考」的可视闭环。

后端阶段 6/9/12 已交付并用 `PostExamClosureIntegrationTest` 9 条用例覆盖整链，但**闭环至今没有界面**——教师无法演示批改与复核，学生无法申请复核。

对应后端 `GradingController`、`ScoreController`、`ScoreReviewController`（已核实存在）。

**前置依赖**：阶段 22 `add-frontend-student-taking`（答卷已可产生）必须先合入。

## What Changes

在 `frontend/src/pages` 下新增考后模块：

**教师侧**

1. **批改工作台**：待批改答卷队列 → 逐题打分 + 评语；**并发批改冲突按后端乐观锁返回处理**——冲突时提示「已被他人批改」并刷新，**绝不静默覆盖**；
2. **成绩汇总与发布**：客观 + 主观汇总预览、发布前预览、批量发布、撤回（按后端权限与状态约束渲染可用动作）；
3. **成绩导出**：触发后端导出（SXSSF 流式），前端只负责下载与进度提示，不在前端拼 Excel；
4. **缺考名单**：按考试查看缺考标记结果（两条结束路径——自然到点与 force-end——均已由后端标记）；
5. **补考管理**：为特定学生创建补考（独立考试记录 + `parent_exam_id` 关联主考 + `exam_candidates` 准入），界面按后端现有能力渲染。

**学生侧**

6. **成绩查询**：成绩已发布后可见；**复核中按后端语义隐藏成绩**，前端不自行判断隐藏条件；
7. **复核申请**：限次限时由后端校验，前端呈现剩余次数与窗口状态；申请后状态可查（待处理/已处理）；
8. **复核结果**：教师处理后呈现结果与调整说明。

## 风险与诚实边界

- **补考最终成绩不得声称可用**：`spec/README.md` 遗留 #5 已记录——`MakeupScoreService.finalScore` **全仓库零调用**，没有任何暴露「补考最终成绩」的接口。本阶段**只做补考的创建与准入管理界面，不做「主考 vs 补考最终成绩合并展示」**；若需要该展示，先单独立项 `add-makeup-final-score`（后端功能变更），再回头补前端；
- **乐观锁冲突必须可见**：批改并发覆盖是深水区 3 的核心叙事，前端若把冲突静默吞掉，等于把后端做对的事在前端抹掉——冲突提示 + 刷新是硬要求，且有 vitest 用例；
- **复核中隐藏成绩的判定在后端**：前端只按接口返回渲染，不本地推断「是否处于复核中」，否则两端规则漂移会泄露成绩；
- **限次限时不在前端计数**：剩余次数与窗口状态一律取后端返回，前端不做本地倒计时判定资格；
- **导出不在前端拼装**：后端 SXSSF 流式导出是防 OOM 的关键设计，前端用 blob 下载即可，不得改成前端取全量数据再拼表；
- **撤回权限**：撤回属高权限动作（需求规格说明书 §5.2 要求管理员权限 + 记录撤回日志），前端按后端权限返回渲染入口，不自行放宽；
- **不夹带**：考试数据报告 PDF、学情分析、错题本、排行榜均在 v3 砍掉清单内。
