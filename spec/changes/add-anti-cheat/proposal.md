# 提案：防作弊（阶段 7，W8）

## Why

考试闭环跑通后，公平性是考试系统区别于普通答题工具的核心价值。本阶段落地防作弊能力的事件体系——切屏/失焦等可疑行为采集、行为日志时间线、教师监考大屏，是面试弹药 A（策略模式事件体系）的第二处代码载体，与判分的策略模式呼应，形成"加一种事件不动核心"的可扩展设计。

**背景**：
- 防作弊决策已确认（`docs/需求决策记录.md` §3.1-§3.4）：
  1. 切屏只**警告 + 记录，不强制交卷**，教师事后依行为日志判定；
  2. 随机抽题/选项乱序**进入时锁定**（阶段 5 已实现）；
  3. 行为日志**仅教师可见**，可按事件类型/严重度筛选；
  4. 监考大屏展示在线/离线/已交卷人数 + 异常高亮 + 行为时间线。
- 已裁剪不做：人脸识别、设备指纹/IP 白名单、浏览器锁定（见 `docs/面试版实施方案.md` v3 §2.3）。
- 切屏/失焦采集埋点已在阶段 5 预留（`exam_behavior_logs` 表与事件采集），本阶段补齐完整事件体系与教师查看。
- 依赖阶段 4（考试快照/监考数据）与阶段 5（行为日志埋点）。

**当前状态**：阶段 5 已埋切屏/失焦事件落库，但事件类型单一、无严重度分级、无教师时间线视图、无监考大屏。

**期望状态**：考试中切屏/失焦/刷新/交卷异常等事件统一采集（事件类型+严重度）、教师可查行为时间线、监考大屏实时展示状态与异常高亮。

## What Changes

- **事件体系（策略模式）**：通用行为事件采集接口 + 切屏/失焦/刷新等多事件实现，事件类型扩展不动核心。
- **严重度分级**：事件 severity（低/中/高），切屏次数阈值可配置。
- **行为日志时间线**：教师端按考试/学生/事件类型/严重度查看行为时间线。
- **监考大屏**：实时在线/离线/已交卷人数、答题进度、异常高亮（切屏等）、点击查看学生时间线。
- **随机抽题/选项乱序**：已在阶段 5 的进入考试实现，本阶段确认为防作弊能力的一部分已在 spec 体现。

## Impact

### 受影响的规范
- `spec/specs/anti-cheat/spec.md` - 新建（`ADDED`）：行为事件采集、严重度分级、行为日志时间线、监考大屏。

### 受影响的代码
- `anti-cheat` 包（事件策略/采集/查询）、`monitoring` 包（监考大屏实时数据）、复用 `exam_behavior_logs`

### 用户影响
- 教师获得防作弊监控能力（时间线 + 监考大屏）；学生切屏会收到警告提示（不强制交卷）。

### API 变更
- 新增行为事件采集、行为日志查询、监考大屏实时数据等端点。
- 无破坏性变更。

### 需要迁移
- [ ] 数据库迁移（复用阶段 5 的 exam_behavior_logs 表，可能补 severity 索引）
- [ ] API 版本提升

- [x] 文档更新（本提案 + 规范 + 面试弹药 A）

## 时间线评估

小：约 3-4 天（W8，对应执行计划「W8 防作弊（切屏策略模式 + 行为日志时间线）」）。

## 风险

- **事件类型扩展侵入核心** —— 缓解：策略模式，新增事件实现独立类，不修改采集核心。
- **监考大屏实时数据压力** —— 缓解：Redd 轮询 + 在线人数用 Redis 实时计数、快照缓存。
- **切屏误报**（如误触系统弹窗）—— 缓解：只记录 + 警告，教师人工判定，不自动处罚。
- **行为日志量大** —— 缓解：日志分级 + severity 过滤，热点查询加索引。
