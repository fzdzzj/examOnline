# 提案：考试管理（阶段 4，W3-W4）

## Why

题库与组卷就绪后，教师需要能"发布一场考试"，让考试成为可组织的实体——绑定试卷、设定时间窗与时长、管理从创建到成绩发布的生命周期。这是连接"组卷"与"在线答题"的关键枢纽。本阶段只做考试管理（创建/发布/状态机/锁定/快照），交付"一场可以开始、可以结束、状态可追溯的考试"；学生答题与交卷留给阶段 5（交卷链路主战场）。

**背景**：
- 状态机已确认：未开始 → 进行中 → 已结束 → 已批改 → 已发布（见 `docs/需求决策记录.md` §4.3）。
- 关键决策：考试开始后**锁定试卷**（禁止改题/删题/改分值，§4.1）；考试**发布时生成试卷快照**（改题不污染历史，§10.10）；随机抽题/选项乱序**进入时锁定一次**（§3.4）。
- 教师提前结束考试：按最后自动保存强制交卷（§1.5，受阶段 5 交卷能力约束，本阶段仅预留状态位）。
- 个人倒计时从"点击开始考试"才计时（§7.9），服务端时间为准（§1.1）—— 这些约束在阶段 5 答题端落地，本阶段只存 `duration_minutes` 与时间窗。
- 依赖阶段 3（add-question-bank）的试卷与快照能力。

**当前状态**：阶段 3 完成后有题库、组卷、抽题锁定快照，但无"考试"实体，教师无法创建/发布考试。

**期望状态**：教师可创建考试（绑定试卷/班级/时间窗/时长）、定时发布、通过状态机管理生命周期；考试发布即生成考试级快照；考试开始后试卷锁定；历史考试与快照可追溯。

## What Changes

- **考试实体**：`exams` 表（title/paper_id/course_id/class_id/start_time/end_time/duration_minutes/status/anti_cheat_config/allow_late_minutes）。
- **考试快照**：`exam_snapshots` 表，发布时序列化完整考试 + 试卷快照（含题目/答案/分值/乱序），后续答题/判分/回看一律读快照。
- **状态机**：`0未开始 → 1进行中 → 2已结束 → 3已批改 → 4已发布`，用乐观锁 CAS 保证并发安全（`UPDATE ... WHERE status=? AND version=?`）。
- **创建/发布**：创建考试（绑定试卷与班级、设定时间窗与时长、防作弊配置）；发布（学生可见，支持定时发布——到达 start_time 自动进入进行中）。
- **试卷锁定**：考试开始（进入进行中）后禁止修改试卷/题目/分值。
- **教师提前结束**：预留 `force_end` 卡片（本阶段迁移到已结束并记录，实际强制交卷逻辑在阶段 5 接入）。
- **数据隔离**：教师 owner 校验（复用 `assertTeacherOwns` 模式）。

## 风险

- **状态机并发脏写**（发布/结束/批改并发流转）—— 缓解：乐观锁 `WHERE status AND version`，影响行 0 重试或报错误码。
- **定时发布依赖时钟** —— 缓解：以服务端时间为准；定时发布用启动时扫表 + 定时任务推进（不依赖外部调度中间件）。
- **快照与试卷不同步** —— 缓解：发布是快照生成的唯一时机，快照只写一次，天然一致。
- **提前结束与交卷竞态**（阶段 5 才接入交卷）—— 缓解：本阶段仅迁移状态并留 `force_end` 标记，交卷完成态由阶段 5 统一处理。
