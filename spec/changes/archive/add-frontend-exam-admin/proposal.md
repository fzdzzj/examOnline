# 提案：教师端考试管理、班级与监考界面（阶段 21，方向③）

## Why

方向③把 `exam-management`（创建/发布、状态机、试卷快照）、`class-management`（班级 CRUD、入班/转班、学生列表）与 `anti-cheat` 的行为日志查询变成教师可操作的考务界面，并接上阶段 11/16 已交付的观测能力做**监考视角**。

本方向是方向④（学生端考试）的前置：考试必须先被创建并发布，学生才可能进入。

对应后端 `ExamController`、`ClassController`、`MonitorController`、`BehaviorLogController`（已核实存在）。

**前置依赖**：阶段 20 `add-frontend-teacher-authoring`（试卷已可产出）必须先合入。

## What Changes

在 `frontend/src/pages` 下新增教师端考务模块：

1. **班级管理**：班级 CRUD、学生入班/转班、班级学生列表（分页）；
2. **考试创建**：绑定试卷 + 班级 + 时间窗（start_time/end_time）+ 个人时长（duration_minutes）+ 迟到允许分钟 + 防作弊配置（按后端 `anti_cheat_config` 现有字段渲染，不扩字段）；
3. **考试列表与状态机可视化**：状态（未开始/进行中/已结束/已批改/已发布）以标签呈现；**状态迁移由后端状态机驱动**，前端只展示当前状态与可用操作，不自行推算下一状态；
4. **发布 / 强制结束**：发布考试（生成试卷快照）、force-end 提前结束；两个动作都有二次确认，因为 force-end 会触发缺考标记；
5. **考试详情**：试卷快照只读预览、考生名单、提交进度；
6. **监考视图**：在线/提交进度、行为日志时间线（按学生查看切屏等事件与 severity）；
7. **观测入口（只读）**：链到阶段 11/16 已交付的 Grafana 面板地址，不在前端重做图表。

## 时间线评估

中：约 2–3 天。

## 风险

- **状态机权威在后端**：前端若自行推算「进行中→已结束」会与 `ExamStateMachineService.autoAdvance()` 漂移；只按接口返回渲染状态与可用动作；
- **force-end 的副作用必须显式提示**：它会触发缺考标记（阶段 12 修过的路径），确认弹窗需写明后果，避免教师误操作；
- **防作弊配置字段**：只渲染后端已有字段，不新增前端专有配置项；
- **监考实时性**：不做 WebSocket 自建推送（v3 未含），用 vue-query 轮询并明确刷新间隔；不得声称「实时」，只能声称「准实时轮询」；
- **不重做观测面板**：Grafana 已有面板，前端只给入口链接，避免两套图表口径不一致；
- **越权**：教师只能操作自己的考试（后端 `assertTeacherOwnsExam` 同类校验），前端不做「隐藏按钮即安全」的假设。
