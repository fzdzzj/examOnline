# 提案：用户认证与鉴权（阶段 2/2，W1-W2）

## Why

骨架就绪后接入认证业务，这是所有业务能力的前置。考试系统对安全与并发有更高要求：Access Token 考试中途过期会中断作答、Token 泄露需能主动失效、教师需隔离各自数据防越权、登录需防暴力破解。本阶段是面试弹药 B（安全体系）的代码载体。

**背景**：
- 双 Token（Access 30min + Refresh 7d + 轮换 + 复用检测）、Redis 黑名单踢人、角色 AOP、登录锁定（5 次锁 15 分钟）均已确认（见 `docs/需求决策记录.md`）。
- 账号标识：学生=学号、教师=工号；注册：学生自助 + 教师邀请码；密码找回：邮箱验证码；权限模型：完整 RBAC（用户-角色-权限五表）—— 均已确认。
- 依赖阶段 1（add-project-skeleton）的 RBAC 五表与统一响应/异常。

**当前状态**：阶段 1 完成后工程可编译、可启动，但无任何认证业务，无用户可登录，接口无鉴权。

**期望状态**：注册 → 登录 → 双 Token 签发 → 刷新轮换 → 黑名单失效 → RBAC 授权 → 越权防护 → 锁定限流 → 密码找回 → 管理员初始化 全链路跑通，核心链路有测试覆盖。

## What Changes

- **注册**：学生以学号自助注册（默认 STUDENT）；教师以工号 + 邀请码注册（授予 TEACHER）；管理员生成/作废邀请码。
- **登录**：账号（学号/工号）+ 密码，密码不可逆哈希存储；失败统一提示防账号枚举。
- **双 Token**：Access 30min（含 jti/角色/权限）+ Refresh 7d；刷新时轮换 + 复用检测（旧 Refresh 复用即全端下线）。
- **主动失效**：Redis 黑名单（登出/踢人/改密码写入 jti）；`AuthenticationInterceptor` 校验 + 查黑名单。
- **密码找回**：SMTP 发送单次验证码（Redis 5 分钟有效），校验后重置并使旧 Token 全失效。
- **RBAC 授权**：`@RequireRole`/`@RequirePermission` 注解 + AOP 切面；`SecurityUtil` ThreadLocal 上下文；角色层级 ADMIN > TEACHER > STUDENT。
- **水平越权防护**：Service 层 owner 校验（如 `assertTeacherOwnsExam`）。
- **登录锁定 + 限流**：连续 5 次失败锁 15 分钟（Redis 计数）；登录接口令牌桶限流。
- **管理员初始化**：启动检测无 admin 则创建并绑定 ADMIN 角色与全量权限。

## Impact

### 受影响的规范
- `spec/specs/authentication/spec.md` - 追加认证能力需求（`ADDED`）：注册、登录、双令牌、主动失效、密码找回、授权、越权、锁定、限流、初始化。

### 受影响的代码
- `auth` 包（Controller/Service/JwtUtil/拦截器/AOP）、`user` 包（账号查询/改密码）、邮件模块

### 用户影响
- 学生/教师获得注册、登录、续期、登出、找回能力；接口开始鉴权。

### API 变更
- 新增 `POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/refresh`、`POST /api/auth/logout`、密码找回端点、邀请码管理端点。
- 无破坏性变更（骨架上无业务端点）。

## 风险

- **Refresh 轮换并发竞态**（同时刷新导致复用误判）—— 缓解：原子轮换 + 复用检测窗口，误判仅下线该用户。
- **账号枚举**（登录返回"用户不存在"暴露账号）—— 缓解：统一返回"账号或密码错误"。
- **越权遗漏**（仅靠前端隐藏按钮）—— 缓解：鉴权与 owner 校验全部在 Service 层后端实现。
- **邮件服务不可用导致无法找回** —— 缓解：验证码过期可重发、记录发送失败日志、管理员兜底重置。
