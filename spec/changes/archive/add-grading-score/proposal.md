# 提案：判分与成绩（阶段 6，W7）

## Why

交卷链路就绪后，答卷需要被评分、成绩需要可发布可导出，形成完整闭环的终点。判分是面试弹药 A（策略模式）的代码载体——客观题自动判分、简答人工批改，题型扩展不动核心；成绩管理则是状态机（已结束→已批改→已发布）在业务侧的收尾。

**背景**：
- 判分决策已确认（`docs/需求决策记录.md` §8.9-§8.10、§7.5-§7.6）：
  1. 客观题：单选/判断精确匹配，多选**漏选部分分、错选/多选 0 分**（部分分系数首版用全局默认 1.0，场次粒度配置留待后续变更 `add-partial-score-config`，见 §风险/§后续）；
  2. 简答：关键词初判 + 教师人工批改，**逐题批改**，评语留痕；
  3. 判分失败**标记可重判**，不影响他人；
  4. 批改未完成**允许发布 + 标记"部分批改"**，未批题目按 0 分。
- 成绩决策已确认：发布前预览、撤回需管理员 + 审计、导出 Excel + 打印 PDF（SXSSF 流式防 OOM）、排名并列同名次、学生仅见自己成绩。
- 唯一一道已有伏笔：答案归一化在阶段 3 已做（判断 T/F、多选有序），判分直接复用。
- 依赖阶段 4 的考试快照（判分读快照拿标准答案）与阶段 5 的答卷数据（阶段 5 交卷只存答案，本阶段补判分）。

**当前状态**：阶段 5 完成后答卷已落库（answers JSON），但无判分、无成绩、状态机停留在"已结束"。

**期望状态**：交卷后客观题自动判分、简答教师逐题批改、成绩汇总（客观+主观）、发布/撤回/导出、判分失败可重判。

## What Changes

- **判分引擎（策略模式）**：题型判分策略接口 + 单选/多选/判断/简答四实现，新增题型不动核心。
- **客观题判分**：按考试快照标准答案 + 归一化答案比对；多选漏选部分分、错选 0 分；判分结果落 `objective_score`。
- **简答批改**：关键词初判（提示分）+ 教师逐题批改工作台（`subjective_grades` 表，评语/批改人/时间留痕）。
- **成绩汇总**：客观 + 主观加权 = `total_score`；并发批改用乐观锁防覆盖。
- **成绩发布/撤回**：已批改 → 已发布（发布前预览）；撤回需管理员权限 + 审计日志。
- **成绩导出**：Excel（全班成绩单/逐题明细/题目统计/个人成绩单）+ 打印 PDF，SXSSF 流式防 OOM。
- **判分失败处理**：标记"判分失败"，支持重判/手动给分。

中：约 5-6 天（W7，对应执行计划「W7 判分+简答批改+成绩」）。

## 风险

- **判分结果与标准答案不一致**（归一化遗漏）—— 缓解：判分复用阶段 3 归一化工具，单元测试覆盖各题型边界。
- **并发批改覆盖**（两教师同批一份卷）—— 缓解：`subjective_grades` 乐观锁 version。
- **导出大文件 OOM** —— 缓解：SXSSF 流式写 + 分批查询。
- **简答关键词初判误伤** —— 缓解：初判仅为提示分，教师人工批改覆盖，不自动定分。
- **多选部分分系数场次粒度缺失** —— 首版本提案只在全局配置默认 1.0，不改 exams 表结构；场次粒度配置（exams 表加 `partial_score_ratio` 字段 + 判分接入）作为独立后续变更 `add-partial-score-config`。

## 后续变更意向

- `add-partial-score-config`：给 exams 表增加多选部分分系数字段，判分读取场次配置，兑现 §8.9 原意。本提案范围不包含该表结构变更。
