# 提案：学生端在线考试界面（阶段 22，方向④·面试主战场）

## Why

方向④是**整个前端的面试主战场**。后端阶段 5/10/13 已把交卷链路做成三重幂等 + MQ 削峰 + 定时兜底 + 多实例扫描安全，但这些能力**至今只能靠 curl 证明**。本方向让「双击不重复、断网不丢答案、倒计时归零只交一次、切屏被记录」在前端真实发生并可演示——把深水区 1 从「我说它有」变成「我能演示它有」。

对应后端 `ExamTakingController`（已核实存在）。

**前置依赖**：阶段 21 `add-frontend-exam-admin`（考试已可发布）必须先合入。

## What Changes

在 `frontend/src/pages` 下新增学生端考试模块：

1. **考试列表**：待考 / 进行中 / 已完成三态；迟到允许窗口的可用性按后端返回渲染；
2. **进入考试**：拉取个人试卷快照（进入即锁定，防换题）；同一学生同一考试只有一个进行中会话的语义由后端锁保证，前端按错误码提示而非自行加锁；
3. **答题界面（极简）**：题目导航（已答/未答/当前）、上一题/下一题、单选/多选/判断/简答四种作答控件。**按 v3 砍掉清单不做计算器、不做标记备注**；
4. **倒计时**：以**服务端时间为准**计算剩余时长，前端只展示；本地归零即**锁定答题界面并标记「待同步」**，网络恢复后按锁定状态提交，服务端仍以服务端时间兜底校验（对齐《需求决策记录》既有决策）；最后 5 分钟警告；
5. **自动保存与断线恢复**：30s 定时保存草稿到后端；**同时写 IndexedDB 本地缓存**，宕机期间作答不丢失；服务恢复后自动同步本地缓存并更新自动保存；重进考试时先拉后端草稿，与本地缓存按时间戳/version 合并，冲突以较新为准；
6. **交卷**：手动交卷二次确认（提示未答题数）；超时自动交卷；**前端提交按钮点击后立即置为 pending 并禁用**，配合后端三重幂等，避免双击/弱网重试产生重复请求；交卷失败保留答案并可重试，不静默丢弃；
7. **切屏检测与上报**：`visibilitychange` + `blur` 记录次数与时长，按后端行为日志接口上报；**只弹警告 + 记录，不强制交卷**（对齐既有决策：是否作废由教师事后依据行为日志判定）；
8. **交卷结果页**：客观题即时出分（后端已支持时呈现），主观题待批改状态如实展示，不猜分。

## 待用户决策的既有冲突

《需求决策记录》第 337 行已记录未决冲突：答题界面「极简不做」（§12.4）vs 草稿画板「附答卷」（§10.4）。

**本提案默认不做草稿画板**，理由：v3 砍掉清单以极简为先；画板涉及 Canvas 存储、图片随答卷提交与后端附件能力，属独立功能变更。若用户要求做，单独立项 `add-frontend-scratchpad`，不塞进本阶段。

## 风险

- **前端时间不可信**：倒计时必须基于服务端时间，禁止用 `Date.now()` 本地推算作为交卷判定依据；本地归零只做「锁定 + 待同步」，最终判定在后端；
- **重复交卷**：前端置 pending 只是体验层，**权威仍是后端三重幂等**；不得在前端用「本地标记已交卷」代替后端结果，否则弱网下会出现「前端说交了、后端没收到」；
- **草稿冲突合并**：IndexedDB 与后端草稿合并规则必须以时间戳/version 为准且**方向保守**（宁可保留较新一份并提示，不静默覆盖学生答案）；合并逻辑必须有 vitest 单测；
- **自动保存风暴**：30s 定时 + 5000 并发是后端已压测过的路径，前端不得改成「每次按键即保存」；输入用防抖，且防抖间隔不小于后端设计假设；
- **切屏检测边界**：浏览器 API 在多标签/最小化/系统弹窗下语义不同，只记录能确证的事件，**不得**为了「看起来防作弊更强」而虚报事件类型或严重度；
- **不夹带**：离线模式（Service Worker 完整离线作答）、人脸识别、设备指纹、浏览器锁定、IP 白名单均在 v3 砍掉清单内；IndexedDB 本地缓存只服务于「断线期间不丢答案 + 恢复后同步」，不声称离线考试模式；
- **演示证据**：本方向验收必须包含可复现的手动演示脚本（双击交卷、断网续答、归零锁定、切屏记录四条），否则「能演示」不成立。
