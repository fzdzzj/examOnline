# 提案：题库与组卷（阶段 3，W2-W3）

## Why

认证就绪后，教师需要能先"建题"再"组卷"，形成考试内容的供给链路。没有题库，考试/答题/判分全都无从谈起。本阶段一次落地两个紧密耦合的领域：题库（问题域数据）与组卷（问题域到试卷的组装），避免分两个变更反复打通同一批表。

**背景**：
- 题型仅 4 类：单选（1）、多选（2）、判断（3）、简答（4），其余（代码/公式/听力/口语）已裁剪（见 `docs/面试版实施方案.md` v3 §2.3）。
- 标签采用**扁平多选**（学科/难度/题型/自定义）；题目**软删除**（is_deleted）。
- 组卷：**手动选题**（排序/分值覆盖）+ **标签随机抽题**；试卷分值可覆盖题目默认分（`paper_questions.score`）。
- 关键决策已确认：试卷内分值与题库默认分互不影响（§11.1）、抽题进入时锁定（§3.4/§10.10 快照前置伏笔）。
- 依赖阶段 2（add-authentication）的 RBAC 授权与水平越权防护（教师只能管理自己的题库/试卷）。

**当前状态**：阶段 2 完成后有认证与鉴权，但无题目、无试卷、无组卷能力。

**期望状态**：教师可 CRUD 题目（打标签、软删）、手动组卷/标签随机抽题、试卷分值与题目默认分解耦、抽题结果可锁定（为考试快照打基础）。

## What Changes

- **题库**：题目 CRUD（单选/多选/判断/简答）、标签扁平多选、软删除（被引用题目不影响历史）。
- **题目答案归一化**：客观题答案统一存储格式（判断题 T/F、多选有序选项），为判分做准备（判分在阶段 6）。
- **组卷**：手动选题（题号排序、每题分值覆盖）、标签随机抽题（按标签/难度/题型比例抽 N 题）。
- **抽题锁定**：抽题结果生成 `paper_snapshot` 快照（含题目/答案/分值/乱序），后续考试复用快照、刷新不换题。
- **教师数据隔离**：Service 层 owner 校验（复用阶段 2 的 `assertTeacherOwnsExam` 模式，扩展 `assertTeacherOwnsQuestion/Paper`）。

## 风险

- **答案格式不统一导致判分错乱**（判断题存 T/F/正确/错误/A/B）—— 缓解：入库即走归一化工具，存储类型统一。
- **随机抽题 ORDER BY RAND() 慢** —— 缓解：先取 id 再内存 shuffle。
- **软删题目被快照引用** —— 缓解：快照存题目副本，删除题目不影响历史快照。
- **标签扁平结构因查重/筛选需要升级树形** —— 缓解：本阶段扁平实现，预留 tag 表可扩展 parent_id。
