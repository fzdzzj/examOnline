# 提案：接通判分入口并防止未判分答卷被汇总（fix-grading-entry-and-summary-prerequisite）

> **状态：已归档（2026-09-25）。推荐 A 已实施并通过隔离测试验收；共享 dev 真汇总未实跑。** 本提案对 `spec/README.md` 遗留 #18（D2）采取一个用户路径上的闭环方案；服务端汇总写前护栏与前端显式判分入口均已实施，验收边界=隔离单测/页面测 + 已提交 HEAD 全量门禁。既有共享 dev 数据上**未实跑**“跳过判分直接汇总”，不把代码推断与隔离测试说成真机结果。

## Why

- **已核实的入口断点**：`GradingController` 暴露 `POST /api/exams/{examId}/grading/run`，前端生成 SDK 已有 `run`，但 `frontend/src` 非生成业务代码无调用；批改工作台从 `subjective_grades` 读进度/学生行，未运行判分时没有这些行。原走查 23-1 的 `totalStudents=0` 是历史真机观察，当前调用缺口是本次代码复核结果。
- **已核实的旁路风险**：`ScoreService.summarize` 仅校验考试已结束/未发布，`objective_score == null` 被当作零并写总分；`ScoreServiceTest.summarizeTreatsUnscoredGradeRowAsPartialAndNullObjectiveAsZero` 明确覆盖该行为。前端成绩页按考试状态提供汇总入口，前端禁用按钮不能保护直调后端 API。是否应阻断是**产品语义变更**，不是“顺手修空值”。
- **必须守住的反例**：`docs/需求决策记录.md` §7.5 允许主观题未批完按零计入并标记“部分批改”；不能借“判分已完成”要求所有主观终分齐全。纯主观试卷或客观实际得零分也不能误拦——判分成功/手动裁定会写入合法的零分。整场判分的现有编排仅遍历 `STATUS_SUBMITTED` 答卷，即便考试状态允许 GRADED，不能在 UI 上向已汇总考试承诺“重新运行即整场重判”。

## 裁决门（实施前）

**推荐 A：服务端护栏 + 教师显式入口。** 在 `ScoreService.summarize` 对**本次要纳入汇总**的已交卷/已批改答卷先做整场前置校验：`grading_status=判分成功` 且 `objective_score` 非空（合法零分通过）；存在未判/失败即以可观察错误拒绝，**任何答卷总分与考试状态均不得写入**。判分失败仍允许既有单份重判或手动给分；主观题未批完仍走 §7.5 的 partial 语义。空答卷考试的既有行为不在本提案中改写。教师需主动点击工作台“运行判分”，不由汇总接口静默代跑。

**备选 B：仅补前端入口、不改后端汇总。** 实施更少，但直调汇总或教师从成绩页跳过判分仍可能按零写分；不能将 D2 的旁路风险报为已修。若选择 B，须先删改本提案的 score-management delta 与后端任务，明确留下风险，**不得按推荐 A 的验收判据盲勾**。

用户已在本线程明确批准推荐 A；以下任务与规范差异按 A 实施。备选 B 仅保留为裁决背景，**不作为本轮施工分支**。批准是方案决策，不等于护栏已部署。

## What Changes

1. **后端先行护栏（仅批准 A）**：在汇总的第一次写入前校验同一批答卷的判分状态与客观分；失败明确提示先运行判分/处理失败答卷，不把主观未批误报成阻塞。修改现有“null 客观分按零”测试，并先增加可失败的拒绝用例；不得靠放宽断言变绿。
2. **前端显式判分**：在教师批改工作台选择**已结束、尚未汇总**考试后提供“运行判分”入口，调用已生成的 `run` SDK；重跑可能覆盖客观分、但不覆盖教师主观终分，提示该语义并防重复点击。响应的 total/success/failed 与失败答卷须如实显示；total=0 不报“判分成功”；请求成功后刷新题级进度与当前学生行。已批改/已发布状态不展示“整场重判”假入口。
3. **成绩页旁路反馈**：汇总收到上述拒绝时给出可操作的错误提示并引导至批改工作台；不把前端按钮状态冒充后端安全边界。无主观题试卷依然需要运行客观判分，但不要求人工主观批改。
4. **证据与收口**：针对“未运行判分、判分失败、合法 0 分、纯主观、部分主观未批、无已交卷答卷”分别验证边界；前后端门禁各自按当次命令、输出、revision 留在 `tasks.json`。不得在共享 dev 上为取证直接汇总未知成绩；如需真实写路径，先审批可隔离且可恢复的测试数据。

## Impact

- **代码与测试**：`frontend/src/pages/(dashboard)/teacher/grading/`（入口、反馈与定向测试），必要时 `teacher/scores/` 只改错误引导；`src/main/java/com/exam/score/service/ScoreService.java` 与相应服务/集成测试（仅 A）。不修改生成 SDK、不新增判分端点。
- **接口/数据**：既有汇总端点对缺判分数据从“写零”变为可观察拒绝（仅 A，属行为兼容性变化）；不改表、schema 或存量迁移。已存在的历史错误汇总不在本提案自动回滚范围。
