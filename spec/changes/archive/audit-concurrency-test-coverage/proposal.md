# 提案：并发边界测试覆盖盘点补强（前后端优化组合·提案⑬，P3）

## Why

全维度勘察定位了后端三处并发边界，其**测试覆盖**未被系统盘点过：`CacheMutexLoader` 的败者等待与超时兜底分支、状态机 CAS 更新 0 行路径、交卷锁 token 过期易主的解锁场景。实现本身经勘察判定为正确设计（组合 spec「假阳性排除清单」已明示不改实现），**缺的是「这些边界分支是否有测试守住」的盘点证据**。

本变更是纯测试加固：只补测试不改实现；若盘点显示已覆盖，如实收窄。属后端独立立项，不塞进前端阶段 19–23 串行链。

## What Changes

1. **盘点**：三处边界逐分支列出「已覆盖（对应测试名）/ 未覆盖」的映射清单，盘点结果入本变更目录；
   - `CacheMutexLoader`：败者等待轮询回填、等待超时兜底直源、空标记命中分支；
   - 状态机 CAS：并发竞争败者（更新 0 行）路径；
   - 交卷锁：token 过期易主后按 token 解锁不误删他人锁；
2. **补测试**：未覆盖分支补集成/单元测试——纯逻辑分支用纯 JUnit（不依赖 Spring），集成场景走既有集成测试框架；**不引入 `@Sql` 自建表**（AGENTS.md 硬约定 2）；
3. **如实收窄**：已覆盖的登记对应测试即可；判定「不需要测试」的分支写明理由；
4. CI 基线（surefire 计数）只增不减；不为凑覆盖写弱断言。

## Impact

### 受影响的规范
- 无 spec-delta：纯测试盘点补强，不改变任何行为规范。多实例扫描幂等是有意设计（组合 spec 假阳性排除清单），**不得当缺陷修**。

### 受影响的文件
- `src/test/**`（仅新增测试文件）
- 本变更目录内的盘点清单

### 需要迁移
- [ ] 数据库迁移
- [ ] 业务 API

## 时间线评估

小：约 0.5–1.5 天（盘点 0.5 天 + 补测试视缺口数量）。

## 风险

- **只补测试不改实现**：若某分支测试写不红/绿不了，说明实现与理解有偏差——停下回报，不得改实现凑测试，也不得删断言凑绿；
- 并发测试须确定性可判（fake 时钟 / 受控栅栏），不写「跑一万次碰运气」的 flaky 测试；
- 测试遵守工程约定：纯 JUnit 优先、不依赖 Spring、不引入 `@Sql`；
- 盘点暴露实现级缺陷（而非测试缺口）时：停下回报另立项。
