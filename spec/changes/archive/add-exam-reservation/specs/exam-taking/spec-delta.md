# add-exam-reservation spec-delta（exam-taking）

能力域：`spec/specs/exam-taking/spec.md`（收口时 ADDED Requirement 合入该基线末尾，Scenario 文本逐字一致）

变更类型：ADDED Requirement

## ADDED Requirement: 考试预约与开考提醒

教师可为普通考试（非补考）开启「需预约」（`reservation_required`，默认关闭）。开启后学生须先预约方可进入；预约名单在开考瞬间锁定，缺席与应考统计按该名单计（「预约即应考」）；开考前系统向预约学生投递一次站内开考提醒。

#### Scenario: 预约窗口与名单锁定

GIVEN 教师创建考试时开启「需预约」且考试已发布、未开始

WHEN 学生在发布后、开始前预约或取消预约

THEN 预约成功（取消即物理删除，重新预约可再次成功，`uk_reservation_exam_student` 唯一索引保证一人一场至多一条有效预约）

AND 考试状态推进为进行中后预约名单锁定：不可再预约、不可再取消

#### Scenario: 未预约者不可进入

GIVEN 「需预约」考试处于进行中

WHEN 未预约学生请求进入考试

THEN 服务端拒绝进入（FORBIDDEN），已预约学生正常进入

AND 首次进入才做本校验：已有答卷者（在考中/已交卷）刷新与断线重连不受预约校验影响，既有准入两层（班级归属/补考白名单）先于本校验、语义不变

#### Scenario: 预约资格与准入口径同源

GIVEN 学生不属于考试绑定的班级

WHEN 该学生请求预约该考试

THEN 服务端拒绝预约（资格校验与进入准入同源，不另造第二套口径），已发出的有效预约名单中不存在外班学生

#### Scenario: 开考提醒行级幂等投递

GIVEN 「需预约」考试已发布且未开始，存在未投递提醒的有效预约，开考时间距当前时刻不超过提醒提前量（配置项，默认 30 分钟）

WHEN 提醒扫描运行（定时扫描 + 启动补偿，同构既有 sweep 模式）

THEN 每条预约恰好投递一条开考提醒消息（行级幂等标记：投递成功即回填，重复扫描、重启、多实例竞争均不重发）

AND 提醒消息经学生消息中心可读，未读状态正确

#### Scenario: 学生消息中心

GIVEN 学生已登录

WHEN 学生查询本人消息列表、未读数或标记某条消息已读

THEN 仅返回本人消息（按用户隔离），未读数与列表状态一致，已读后未读数减少

AND 端点仅要求登录鉴权，不特判角色

#### Scenario: 学生考试列表下发预约状态

WHEN 学生查询本人考试列表

THEN 列表项下发 `reservationRequired` 与 `reserved` 两字段（本人在该场考试的有效预约状态）

AND 「需预约」考试未预约时即便处于进行中 `canEnter` 亦为 false；非预约制考试列表行为与既有契约零变化（新字段默认值除外）
