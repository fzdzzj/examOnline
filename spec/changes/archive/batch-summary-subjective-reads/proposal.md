# 提案：汇总时一次取出主观分（batch-summary-subjective-reads）

> 状态：已归档（2026-09-25）。验收边界=ScoreServiceTest 40/0/0（隔离单测，命令、原始输出与 revision 见 tasks.json 证据字段）；这不是交卷 P99 修复；未跑共享 dev 真汇总。只减少查询次数，不改汇总语义。

## Why

`ScoreService.summarize` 先一次取出本场待汇总答卷，再对每一份答卷单独查询 `subjective_grades`。这是代码里能数清的 N+1。交卷入口和消费端 JDBC batch 没有这个形态。学生考试列表已经用一次 `IN` 查询，题目标签也是批量取出。

这不是交卷延迟剖面。没有证据说它是交卷 P99 的主体。它只是调用次数上已经数清、且可以在不改分数语义的前提下降下来的一类。

**当前状态**：有简答题时，汇总的主观分查询次数等于答卷份数。

**期望状态**：同一场汇总最多一次取出这些答卷的主观分，总分、部分批改标记和「未判完拒绝整场」保持不变。

## What Changes

- 在进入逐份 CAS 之前，按本场答卷 ID 一次查询主观分。
- 保留现有护栏：未判完或客观分为空则整场拒绝且不写；合法零分和未批主观的部分批改规则不变。
- 用现有 `ScoreServiceTest` 扩展覆盖「多份答卷只查一次主观分」。不改 JVM、线程池、交卷路径。
