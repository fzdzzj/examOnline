## 一、测量有效性（与裁决分离）

三次运行的有效性闸门 G1–G6 全部成立（`rounds-analysis.json:validity.pass=true`，21 项检查逐条 OK）：

- **G1 语义 oracle（G1）**：每次运行 12 条语义用例全绿——`passLine=null` 只返缺考；`passLine=-1`；
  `60 / 60.00 / 60.000` 三种 scale 同结果；严格小于边界（`=60` 不入选，`=60` 的 null 总分排除）；
  缺考∪低分并集；同 ID 低分原因覆盖缺考；缺失姓名（`null`）与软删姓名（`is_deleted=1`）；
  两个空候选形状**姓名查询次数为 0**（短路成立）；非归属 403；不存在 404；已软删考试 404；ADMIN 放行。
- **G2 夹具 oracle（G2）**：6 个 combo 的候选规模与原因计数由夹具参数独立推算并与生产结果一致（`oracles=6`）。
- **G3 结果等价（G3）**：全部 24 轮 × 3 次运行，四路 canonical（prodFirst、prodLast、OLD、PUSHDOWN、PROJECTION）
  按 `(studentId|reason|name)` **排序集合**相等（不制造现行查询没有的排序契约）。不等价会使工具直接抛错废轮；
  三次运行无一轮触发。
- **G4 受控臂形状（G4）**：SQL 捕获生效且经原文核验：PUSHDOWN 的答卷 SQL **有且仅有**多出 `total_score < ?`；
  PROJECTION **有且仅有**收窄列（去掉 `answers`）。任一不符即废轮；24/24 轮通过。
- **G5 探针隔离（G5）**：请求级批量样本在 SQL 捕获关闭状态采集；分相位探针是额外一遍完整路径，单列上报，
  不并入请求级均值。
- **G6 独立性（G6）**：三次独立 JVM；每 combo/臂预热 2 次不计入窗口；每轮 4 次重复原样上报，未挑轮。

口径边界（随结论一同生效）：隔离 H2 + 进程内直调，非 MySQL/Tomcat；`answers` 体量是 Java 侧字符统计
（ASCII 夹具 1 字符 = 1 字节），**不是网络传输字节**；相位是墙钟（含 JDBC/映射/分配）；比值为同轮 mean 商，
**不跨轮或跨窗口相减求占比**；分配量为 `ThreadMXBean.getCurrentThreadAllocatedBytes` 单线程窗口差分。

## 二、裁决（按冻结算子逐条）

| 判据 | 结果 | 依据 |
|---|---|---|
| D1 低分取回+Java 过滤是占比最高的可控因素 | **false** | `s200-p10-a2k` 有 5/12 个样本不成立（见下） |
| D2 下推收益每一轮都越过波动带 | **false** | `s200` 下推比值最小值 1.317 < 判定带 1.797；`a20k` 最小值 2.399 < 判定带 3.518 |
| D3 行为等价 | true | G3 全轮成立 |
| D4 收益不只是人为极端形状 | **false** | D4 = D2 且必须含 `s200` 与 `a20k`；D2 已 false |
| D5 投影主导（NO-GO 的另一触发） | false | 主族四形状投影胜出轮次 4/12、0/12、0/12、0/12，均未过半 |
| D6 可靠性 | true | G1/G2/G4/G5 全成立，三次运行 JSON 完整 |

**主族 GO = false。**

### 最强反例（两处，均可复算）

1. **`s200-p10-a2k`：波动吞没收益。** 判定带由上界 1.797 设定（同轮对照的等价副本 `OLD` 臂自身能达到的最慢比值），
   而下推最差一轮只有 1.317，见 `run1` 轮 1：
   `prodFirst=1.722 / prodLast=1.795 / OLD=2.358 / PUSHDOWN=1.335 / PROJECTION=1.213`（毫秒；臂序 `OLD→PUSHDOWN→PROJECTION`）。
   该轮除下推外的三条等价路径同时变慢（同轮 OLD 比值 0.746），说明这是同轮漂移吞掉了收益，而非下推无效。
   同一形状的 D1 也失败：`gradingSelect + Java 过滤` 组在 5/12 个样本里不是最大相位，反例
   `run3` 轮 1 组 = 0.941ms vs `absenceLoad` 1.918ms、`nameLoad` 1.423ms；`run1` 轮 1 组 = 0.653ms vs `nameLoad` 2.290ms。
   即**200 人规模下，低分取回并非本入口占比最高的可控因素**。

2. **`s1000-p10-a20k`：顺序漂移上界使判定带不可达。** 判定带 3.518 由 `run3` 轮 4 的
   `prodFirst=5.118 → prodLast=1.455`（同一入口、同一代码、前后两次）这个同代码漂移样本设定；
   下推最小值 2.399（`run1` 轮 2：`prodFirst=3.896 / prodLast=1.752 / PUSHDOWN=1.177`）低于它。
   若只用 `OLD` 等价臂噪声带（上界 1.565），该形状是越过的——**这一项的失败属"稳定性不达标"，
   而非"收益不存在"**，如实记录以备复核。

### 敏感性读数（证明裁决不是算子歧义的产物）

`PREREGISTRATION.md` 中 D1a 与 D2 的算式留有解释空间，故在裁决之外附四组读数（`sensitivity-check.cjs`）：

| 读法 | 结果 |
|---|---|
| A 冻结读法（D1a 逐样本 + D2 极值） | NO-GO（D1=false D2=false） |
| B 只松开 D1a 为聚合口径 | NO-GO（D1=true D2=false） |
| C 聚合 D1a + D2 只用 OLD 噪声带（去掉顺序漂移项） | NO-GO（D1=true D2=false） |
| D 聚合 D1a + D2 改用中位统计 | GO（D1=true D2=true） |

四种读法中三种仍 NO-GO。唯一翻绿的读法 D 用中位数替换"每一轮"，而提案要求的是
"收益**稳定**超过轮间/探针波动"——中位读法不再检验逐轮稳定性，故**不采用**；
按提案「不得为追求 GO 临时放宽判据」，本裁决冻结在 A。
（需明示：由此本 NO-GO 的性质是**稳定性不达标**，不是"下推在任何口径下都无收益"。）

## 三、方向性支持与形状边界（不作 GO 依据，只作边界披露）

- 下推的**中位**收益在主族四形状为 1.914 / 3.484 / 3.757 / 2.969（请求级均值商），
  并发臂吞吐中位比 `PUSHDOWN/OLD` = 3.691 / 4.852 / 4.961 / 4.851，方向一致且稳定为正。
- 结构可消除量随形状单调：`s200` 消除 368,640 字符（200 行 → 20 行）；
  `s1000-a2k` 消除 1,843,200；`s3000-a2k` 消除 5,529,600；`a20k` 消除 18,432,000（字符，非字节，非网络量）。
- 相位中位构成（`OLD` 探针）显示主族中 `gradingSelect` 在 1000/3000 规模是最大单相位
  （2.332ms / 6.117ms），但 200 规模不是（0.663ms，被 `absenceLoad` 0.440 与 `nameLoad` 0.432 逼近）。
- **边界（敏感族）**：低分占比升高时下推收益衰减并在 p90 不可辨（中位 1.063，最小 0.818），
  且**投影在敏感族多数轮次胜出**（p50 7/12、p90 10/12），p90 的相位中位由 `nameLoad` 主导（3.766ms > `gradingSelect` 2.315ms）。

## 四、未知（不作为任何结论的依据）

- 本端点**真实请求频度未知**：未读共享 dev、未读未授权运行时日志、未采信前端调用点或 dev 演示记录；
  真实考试人数分布、真实 `answers` 字段大小分布同样未知（`runtimeFrequencyUnknown` 字段已在每份运行 JSON 内声明）。
- 真实 MySQL 传输与连接池行为、Tomcat 线程/GC 行为、真实索引统计均未观测；
  `total_score` 目前无索引，但本次测量不构成对 MySQL 执行计划或线上 P99 的任何结论。
- 因此本裁决只能写"隔离负载下不满足预登记的稳定性判据"，
  **不得**外推为"生产上无收益"或"生产上有收益"。
