# 提案：教师端题库与组卷界面（阶段 20，方向②）

## Why

方向②把已交付的 `question-bank` 能力（题目 CRUD、标签、软删除、手动组卷、标签随机抽题、快照锁定）变成教师可操作的界面。这是考试链路上游：**没有试卷就没有考试**，后续方向③④⑤全部依赖本方向产出的试卷。

对应后端 `QuestionController`、`TagController`、`PaperController`（已核实存在）。

**前置依赖**：阶段 19 `add-frontend-skeleton-auth`（工程底座、API 层、角色守卫）必须先合入。

## What Changes

在 `frontend/src/pages` 下新增教师端命题模块：

1. **题库列表页**：分页 + 按题型/标签/关键词筛选；软删除题目的可见性按后端语义呈现（不自行发明过滤规则）；批量选择；
2. **题目编辑**：四种题型（单选 / 多选 / 判断 / 简答）各自表单与校验——单选单选校验、多选至少两项、判断归一化、简答无选项；分值与难度；解析字段；标签多选；
3. **标签管理**：标签 CRUD（按后端 `TagController` 能力，不扩表）；
4. **组卷页（手动）**：从题库选题加入试卷、题号排序、逐题分值覆盖（`paper_questions.score` 可覆盖题目默认分值）、总分实时汇总；
5. **组卷页（标签随机抽题）**：按标签 + 题型 + 数量配置抽题，预览抽中结果后确认入卷；
6. **试卷列表与详情**：只读预览试卷题目与分值分布；
7. **契约一致性**：全部走 `gen:api` 生成客户端，禁止手写重复接口定义。

## 时间线评估

中：约 2–3 天。

## 风险

- **题型表单差异**：四种题型字段不同，用题型驱动的表单配置而非四份复制粘贴代码；新增题型时只加配置；
- **答案归一化在后端**：前端只做录入与格式校验，**不得**在前端实现判分口径的答案归一化（后端 `TopicAnswerContractUtil` 同类职责），否则两端漂移；
- **随机抽题结果可重复抽取**：抽题是后端行为，前端只展示结果并允许重抽，不在前端做随机算法；
- **软删除语义**：以接口返回为准，前端不缓存已删题目做「假可用」展示；
- **不做**：Excel 导入、蓝图组卷（双向细目表）、试卷模板版本、AI 生成题目——均在 v3 砍掉清单内，本阶段不夹带；
- **不改后端**：若发现接口缺口（如缺少按标签抽题的入参），停下来回报并单独立项，不在前端用多次请求拼凑绕过。
