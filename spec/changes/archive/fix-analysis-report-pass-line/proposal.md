# 提案：分析报告及格线按试卷总分比例派生（总分非 100 失真修复，fix-analysis-report-pass-line）

> 状态：已立项待执行。阶段 0 查证基于 main `1c8a765`（2026-10-11）现场审计（用户发起「试卷总分非 100 影响面」审计）。审计结论：判卷/成绩汇总/榜单/导出主链路对任意总分安全（题目分值和=试卷总分校验、得分实加、单题满分归一化口径正确）；**唯一失真域为分析报告**——及格线 `PASS_LINE=60` 与分数段 `<60 / 60-89 / 90+` 为绝对值硬编码，150 分试卷下及格语义错乱（60 分仅 40%）、50 分试卷全员不及格；前端 `ExamAnalysisReport.vue`「低于及格线 60 分」文案硬编码与后端双源漂移。

## Why

- **失真实证（`1c8a765` 现场核）**：[ExamAnalysisReportService.java](../../src/main/java/com/exam/score/service/ExamAnalysisReportService.java) L52 `PASS_LINE=60` 绝对常量驱动三处消费（L176 及格率、L184-190 分数段切分、L306 学生关注名单）；前端 ExamAnalysisReport.vue L110 文案硬编码。系统其余域零命中（监控面板 0~100 百分比分母为人数/样本，与分数无关）。
- **修复语义定版（用户裁决「按这个方案来」）**：及格线/优秀线不再绝对——**按试卷总分 × 60% / × 90% 派生（BigDecimal HALF_UP 取整到整数分）**。100 分制下派生值恰为 60/90，与现行为逐字节一致——**向后兼容是硬验收判据，不是目标**。
- **契约面**：及格线/优秀线经 DTO 下发（前端零硬编码、单源化），DTO 加字段触发 openapi 契约同步与前端类型同步——合法契约扩展（schema 加字段，paths 数不变，gate-baseline 合法持平）。

## What Changes

1. **`ExamAnalysisReportService`**：删除 `PASS_LINE` 绝对常量；新增按试卷总分的及格线/优秀线派生（60%/90%，HALF_UP 取整）；试卷总分取数走既有**只读**链路（快照/试卷读取服务，依赖注入，不改 grading/paper 域）；三处消费点（及格率、分数段切分、关注名单）全部改用派生值。
2. **`ExamAnalysisReportResponse`** DTO：新增 `passLine`、`excellentLine` 两整数字段下发（前端渲染单源）。
3. **契约同步**：`openapi.yaml` 重导出（离线路径 A 先例，`getContentAsByteArray()` UTF-8 纪律）；前端 API 类型/SDK 若为生成链则重生成，若为手写类型则同步字段（K 查证后按实况，如实登记形态）。
4. **前端 `ExamAnalysisReport.vue`**：关注名单文案「低于及格线 60 分」→ 按下发 `passLine` 渲染；分数段 label 的硬编码边界值（如有）一并改用 `passLine`/`excellentLine`。
5. **测试（用例只增不减）**：后端单测三分制——150 分制（及格线 90、优秀线 135、三段以 90/135 切）、50 分制（30/45）、**100 分制零回归（60/90 与既有输出逐值对照）**；试卷总分不可得 → 报告接口 fail-fast 明确报错用例；前端文案动态渲染断言（严禁 if/exists 守卫与 || 双通形态——decorative assertions 纪律）。
6. **三件套随实施笔一并入库**。

## Impact

- **规范**：score-management 能力域 ADDED 1 Requirement（六 Scenario，见 spec-delta）。
- **代码**：`src/main/java/com/exam/score/**`（服务 + DTO）与前端分析报告组件受控修改 + 各自测试；`schema.sql`、grading/paper/submission/clazz 等无关域零触碰；无表变更。
- **用户/API**：分析报告响应新增两字段（向后兼容扩展）；非 100 总分试卷的教师端分析报告数值首次正确。
- **行为边界**：100 分制试卷输出零变化（硬判据）；50/150 等总分的及格率/分数段/关注名单改为正确语义。
- **CI**：`gate-baseline.json` 用例数同笔上调（新增后端与前端用例；paths 不变合法持平）——收口笔义务照 AGENTS 门禁条。
- **外发动作授权**：本案验收含 push（feature、main）——派发即视为授权。
- **非目标（显式排除）**：试卷级自定义及格线配置面（60%/90% 比例为定版语义，不做可配置化）；成绩汇总/导出/榜单域（审计已确认安全）；分数段粒度调整（保持三段制）；数据库变更。

## 验收与停止条件

- **三分制对照实测（三要素留证）**：同一份试卷数据在 150/50/100 三种总分下的报告输出对照——150 → passLine=90/excellentLine=135/分数段以 90、135 切；50 → 30/45；**100 → 60/90 且及格率、分数段分布、关注名单与实施前输出逐值一致（零回归）**。
- **门禁**：后端 `mvnw.cmd clean test` 全绿且用例数恰增新增数；前端三门禁（npm.cmd 形态、输出非空）全绿且用例数恰增；`gate-baseline.json` 同笔上调对齐。
- **契约**：重导出 `openapi.yaml` 与真实 dev 实例 `/v3/api-docs.yaml` 字节级一致（先例纪律）；schema 仅新增两字段、paths 零变化。
- **停止条件**：① 试卷总分取数须修改 grading/paper 域既有代码才能打通 → 停止上报（只许只读注入）；② 100 分制输出出现任何回归 → 停止上报，不得以「调整测试预期」消化；③ 契约重导出与真实实例比对经两轮排查仍不一致 → 停止；④ 发现既有前端用例以硬编码 60/90 断言而须删除才能通过 → 停止上报裁决（删除断言属用例下降，须替换而非删除）；⑤ 派生取整策略 HALF_UP 在任何总分下产生非整数分边界歧义且无法以测试钉死 → 停止上报。
