> **文档版本**：v1.0
> **编制日期**：2026-09-10
> **基于**：newLab 后端源码分析 + 用户需求调研
> **目标读者**：开发团队（1-2 人全栈）、产品负责人、技术决策者

---

## 一、项目定位与约束

### 1.1 核心定位

**高校课程考试平台**，面向期末/期中/随堂测验场景，支持几百到几千人规模，强调**公平性**（防作弊）和**成绩汇总**（自动化分析）。

### 1.2 关键约束

| 维度 | 约束 | 影响 |
|---|---|---|
| **团队** | 1-2 人全栈 | 技术选型必须成熟稳定，避免冷门框架；前后端分离但一人兼顾 |
| **预算** | 低预算（开源为主） | 人脸识别/AI判分/OCR 等商业服务需找开源替代或延后 |
| **周期** | 无明确 deadline | 可分阶段迭代，质量优先 |
| **数据** | 无历史数据迁移 | 全新设计，无兼容包袱 |
| **并发** | 1000-10000 | 必须 Redis + 消息队列 + 读写分离 |
| **部署** | 公有云 | 阿里云/腾讯云，弹性扩容，按需付费 |

### 1.3 设计原则

1. **MVP 优先**：先跑通"登录→题库→组卷→考试→判分→成绩"闭环，再叠加防作弊/数据分析
2. **模块化**：题型/判分/防作弊/导入 均用 Strategy Pattern，新增不动核心
3. **开源优先**：能用开源不用商业，能用成熟轮子不自研
4. **渐进增强**：第一版 Web 端，第二版 App，第三版 AI

## 三、创新点与差异化竞争力

### 3.1 核心创新（建议优先实现）

| # | 创新点 | 价值 | 实现难度 | 建议阶段 |
|---|---|---|---|---|
| 1 | **蓝图组卷（双向细目表）** | 保证试卷覆盖度和难度分布，教师只需填矩阵 | ⭐⭐ | MVP |
| 2 | **AI 辅助组卷混合流** | AI 生成初稿 → 教师下载 Word 修改 → 上传终版，兼顾效率和质量 | ⭐⭐⭐ | V2 |
| 3 | **错题本 + 消灭计划** | 自动归集错题，连续 3 次做对自动移出，形成学习闭环 | ⭐⭐ | V2 |
| 4 | **考试数据分析报告** | 自动生成 PDF（难度系数/区分度/知识点薄弱点），教师可直接用于教学改进 | ⭐⭐⭐ | V2 |
| 5 | **离线考试模式** | Service Worker + IndexedDB，断网可继续作答，恢复后自动同步 | ⭐⭐⭐⭐ | V3 |

### 3.2 技术创新（开源方案替代商业服务）

| 需求 | 商业方案 | 开源替代 | 备注 |
|---|---|---|---|
| 人脸识别 | 百度AI/腾讯云 | OpenCV + FaceNet/ArcFace | 准确率稍低，但够用 |
| OCR 识别 | Mathpix/ABBYY | PaddleOCR + 自定义 NLP | 公式识别准确率 85%+ |

### 3.3 体验创新

- **考前设备检测**：自动检测摄像头/麦克风/浏览器版本/网络延迟，生成"设备就绪度报告"

- **考后即时解析**：交卷后立即显示错题解析（可配置是否延迟发布）
- **班级排行榜**：匿名显示前 10 名（保护隐私），激励竞争
- **教师监考大屏**：实时显示所有学生状态（在线/离线/切屏次数/进度），异常高亮

## 四、必须点（不做系统无法上线）

### 4.1 安全必须

- [ ] **JWT 双 Token 机制**：Access Token（短效 30min）+ Refresh Token（长效 7d），防止考试中途过期
- [ ] **密码 BCrypt 加密**：禁止明文/MD5/SHA1
- [ ] **SQL 注入防护**：MyBatis-Plus 参数化查询，禁止字符串拼接
- [ ] **XSS 防护**：前端输入过滤 + 后端输出转义（题目内容可能含 HTML）
- [ ] **CSRF 防护**：SameSite Cookie + CSRF Token
- [ ] **文件上传安全**：类型白名单 + 大小限制 + 病毒扫描（ClamAV）+ 存储隔离
- [ ] **敏感数据加密**：身份证号/手机号/人脸特征 AES 加密存储
- [ ] **操作审计日志**：所有增删改操作记录（谁/何时/改了什么）

### 4.2 可靠性必须

- [ ] **事务一致性**：交卷 + 判分 + 落库必须原子（@Transactional）
- [ ] **幂等性**：交卷接口防重（唯一索引 + 乐观锁）
- [ ] **断线恢复**：自动保存答案（Redis + 定时落库），重新登录可继续
- [ ] **超时自动交卷**：倒计时归零强制提交（前端定时器 + 后端兜底）
- [ ] **并发控制**：同一考试同一学生只能有一个进行中会话（Redis 分布式锁）
- [ ] **数据备份**：每日全量 + 实时 binlog，支持按时间点恢复

### 4.3 性能必须

- [ ] **Redis 缓存**：题目/试卷/用户信息热点数据缓存（TTL 5min）
- [ ] **消息队列**：判分/通知/日志异步处理（RabbitMQ/RocketMQ）
- [ ] **数据库索引**：exam_id + student_id 联合索引，submission_time 索引
- [ ] **分页查询**：禁止全表扫描，强制 LIMIT
- [ ] **静态资源 CDN**：题目图片/音频/视频走 OSS + CDN
- [ ] **接口限流**：Sentinel/Guava RateLimiter，防止恶意刷接口

### 4.4 合规必须

- [ ] **个人信息保护**：符合《个人信息保护法》，隐私政策 + 用户协议 + 单独同意
- [ ] **数据本地化**：教育数据不出境（公有云选国内区域）
- [ ] **等保三级**：若服务高校，需通过等保测评（日志留存 6 个月+）
- [ ] **未成年人保护**：若涉及中学生，需家长同意机制

## 五、注意点（容易踩坑的地方）

### 5.1 技术坑

| 坑 | 后果 | 规避方案 |
|---|---|---|
| **ORDER BY RAND() 性能** | 题库大时全表扫描，交卷慢 | 先 SELECT id 再内存 shuffle，或用 OFFSET 随机 |
| **AES/ECB 模式不安全** | 同明文→同密文，易被破解 | 改 AES/GCM/NoPadding + 随机 IV |
| **前端时间不可信** | 学生篡改本地时间绕过倒计时 | 以服务端时间为准，前端仅展示；交卷时校验服务端时间戳 |
| **JWT 无状态难踢人** | Token 泄露后无法主动失效 | Redis 黑名单（jti 字段）+ 短效 Access Token |
| **大文件上传超时** | 听力/口语音频上传失败 | 分片上传（tus 协议）+ 断点续传 + OSS 直传 |
| **并发交卷死锁** | 多学生同时交卷，数据库锁竞争 | 消息队列削峰 + 批量插入 + 乐观锁 |
| **离线模式冲突** | 断网期间多设备作答，恢复后答案冲突 | 版本号（version）+ 时间戳，以最新为准 |

### 5.2 业务坑

| 坑 | 后果 | 规避方案 |
|---|---|---|
| **答案格式不统一** | 判断题存 T/F/正确/错误/A/B，判分全乱 | 强制走 TopicAnswerContractUtil 归一化 |
| **题目删除级联** | 删除题目导致历史答卷无法查看 | 软删除（is_deleted）+ 历史答卷快照（存题目副本） |
| **成绩发布撤回** | 发布后发现错误，撤回学生已看到 | 发布前预览 + 撤回需管理员权限 + 记录撤回日志 |
| **补考成绩覆盖** | 补考成绩覆盖原成绩，学生不满 | 保留所有考试记录，取最高分/最后一次（可配置） |
| **教师越权** | A 教师修改 B 教师的试卷 | Service 层加 assertTeacherOwnsExam(examId, username) |
| **学生替考** | 人脸识别通过后换人答题 | 考中定时抽拍（每 5 分钟）+ 异常行为触发即时抽拍 |

### 5.3 运维坑

| 坑 | 后果 | 规避方案 |
|---|---|---|
| **考试高峰期宕机** | 几千人同时交卷，服务器崩溃 | 压测（JMeter）+ 弹性扩容 + 降级预案（关闭非核心功能） |
| **数据丢失** | 数据库故障，答卷丢失 | 主从复制 + 异地备份 + 实时 binlog |
| **日志爆盘** | 行为日志/HTTP 日志占满磁盘 | 日志分级（ERROR/WARN/INFO）+ 定时归档 + OSS 冷存储 |
| **证书过期** | HTTPS 证书到期，全站不可用 | 提前 30 天告警 + 自动续期（Let's Encrypt + certbot） |

### 6.2 技术选型（基于 newLab + 约束调整）

| 层 | 技术 | 理由 |
|---|---|---|
| **后端框架** | Spring Boot 3.5.5 + Java 17 | newLab 已验证，稳定 |
| **ORM** | MyBatis-Plus + AutoTable | 注解建表，快速迭代 |
| **认证** | JWT (jjwt) + BCrypt | 轻量，无需 Spring Security |
| **缓存** | Redis 7.x | 热点数据/分布式锁/会话 |
| **消息队列** | RabbitMQ | 判分/通知异步，削峰 |
| **数据库** | MySQL 8.0（主从） | 成熟稳定，云服务商支持好 |
| **OLAP** | ClickHouse（V2 再加） | 数据分析报表 |
| **文件存储** | 阿里云 OSS + CDN | 图片/音频/视频 |
| **前端** | Vue3 + TypeScript + PrimeVue | newLab 前端同款，学习成本低 |
| **移动 App** | Flutter（V2 再加） | 跨平台，一套代码 iOS/Android |
| **代码判分** | Judge0（Docker） | 开源沙箱，支持 40+ 语言 |
| **OCR** | PaddleOCR | 百度开源，中文识别准确率高 |
| **人脸识别** | OpenCV + ArcFace | 开源，离线部署 |
| **AI 生成** | ChatGLM/Qwen（本地）或 GPT API | 低预算用本地模型 |

## 九、风险与应对

| 风险 | 概率 | 影响 | 应对方案 |
|---|---|---|---|
| **1-2 人开发周期过长** | 高 | 高 | 严格按 MVP 优先级，砍掉非核心功能；用开源轮子不自研 |
| **防作弊功能侵犯隐私** | 中 | 高 | 明确告知 + 单独同意 + 数据本地化 + 定期删除 |
| **高并发宕机** | 中 | 高 | 提前压测 + 弹性扩容 + 降级预案（关闭非核心功能） |
| **AI 生成题目质量差** | 高 | 中 | 教师审核 + 标记 AI 来源 + 逐步优化 Prompt |
| **人脸识别准确率低** | 中 | 中 | 阈值可调 + 人工复核通道 + 降级为拍照存档 |
| **代码题沙箱被攻破** | 低 | 高 | Docker 隔离 + 资源限制（CPU/内存/时间）+ 网络隔离 |
| **数据丢失** | 低 | 极高 | 每日全量备份 + 实时 binlog + 异地容灾 |

## 附录：术语表

| 术语 | 含义 |
|---|---|
| **MVP** | Minimum Viable Product，最小可行产品 |
| **蓝图组卷** | 按双向细目表（知识点×难度）自动抽题组卷 |
| **CAT** | Computerized Adaptive Testing，计算机自适应测试 |
| **难度系数** | P 值，答对人数/总人数，越大题目越简单 |
| **区分度** | D 值，高分组答对率 - 低分组答对率，越大题目越能区分学生水平 |
| **双向细目表** | 知识点×难度的二维矩阵，规定每个单元格抽几道题 |
| **设备指纹** | 基于浏览器/硬件特征生成的唯一标识，用于防替考 |
| **离线模式** | 断网后前端本地缓存答案，网络恢复后自动同步 |
| **Judge0** | 开源代码判分沙箱，支持 40+ 编程语言 |
| **ArcFace** | 开源人脸识别模型，准确率高 |
| **PaddleOCR** | 百度开源 OCR 工具，中文识别准确率高 |
