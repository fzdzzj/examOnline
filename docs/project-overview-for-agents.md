# 项目概览（新 Agent / 协作者速查）

> **定位**：说明项目是什么、三层可回答架构设计、核心业务链路拓扑与关键纪律。
> **事实源原则**：**本文件不承载易变事实**（端口、口令、用例数、覆盖率、表清单一律不写在此处）。各事实源指针唯一定位在根目录 `README.md`；四条硬约定与唯一门禁命令以 `AGENTS.md` 为准。

## 一、项目定位与三层可回答标准

这是基于 Spring Boot 3 + Vue 3 的在线考试系统，定位为**高可靠单体架构与并发边界深水区工程示范**。

衡量一个功能或优化是否值得做的唯一标准：**能否让一条关键路径从「我说它有」变成「我能证明它有」**。每一项核心能力必须在三个层次上能够回答：

- **L1：功能正确**——正常业务流程完整可用；
- **L2：并发边界正确**——并发交卷、重复请求、超时倒计时、进程崩溃、网络抖动下的行为均具备确定性且可解释（幂等守卫、悲观/乐观锁、状态机严格单向推进）；
- **L3：可观测、可恢复、可证明**——具备 Prometheus 指标打点、有界队列与重试、数据保留与定期归档清理、压测基线与变异测试证据。

**架构底线**：单体 Spring Boot + Vue 3 SPA。不要为了“整洁”或“展示”盲目拆分微服务、引入分布式调度（ShedLock/Quartz）或改写稳定运行的单体核心。

## 二、核心业务主线拓扑

系统围绕考试全生命周期构建，核心路径为：

```text
教师出题（题库CRUD/标签/题干图片） 
  → 组卷与快照固化（手动/随机/蓝图组卷，生成试卷快照 PaperSnapshot，锁定后不可篡改）
  → 创建与发布考试（生成考生名单，状态推进至 PUBLISHED）
  → 学生进入考试（服务端时间校准、拉取只读个人快照）
  → 作答与本地缓存（PWA离线壳，定时自动保存草稿至 Redis）
  → 交卷触发（学生主动交卷 / 超时系统自动收卷 / force-end 强制收卷）
  → 三重幂等削峰（Redis 分布式锁 + MySQL CAS 状态机 + 唯一索引防重 → MQ 发送端 Confirm 削峰）
  → 批量落库与异步处理（手动 Ack，异常进入 DLQ 有界留档）
  → 判分与成绩汇总（客观题策略注册表判分、主观题乐观锁并发批改、连对消灭错题本重练）
  → 结果发布与流式导出（SXSSF 逐行流式防 OOM、成绩单 PDF 打印、逐题指标与选项分布分析）
  → 考后闭环（缺考自动标记、独立补考记录、成绩复核受控申请）
```

## 三、真源与规则路由

为防止多副本导致的陈旧漂移，本项目各项信息唯一真源严格收口如下：

| 想要了解的信息 | 唯一出处 | 关键指引 |
|---|---|---|
| 快速开始、服务端口、环境配置与全仓路由 | 仓库根 `README.md` | 本项目只在此处维护事实路由表 |
| 四条硬约定、自查命令、禁忌指针、唯一门禁 | 仓库根 `AGENTS.md` | 会话自动注入，任何改动不得违反 |
| 成熟功能待办、串行队列、候选池 | `docs/功能待办清单.md` | 功能规划唯一依据，按 A/B/C/D 节分类 |
| 架构设计决策与历史推翻方案 | `docs/需求决策记录.md` | 方案取舍与历史决策记录 |
| 能力域需求与验收标准（EARS 规范） | `spec/specs/<capability>/spec.md` | 业务应当表现的行为契约 |
| 当前进行中变更与近期归档速览 | `spec/README.md` | 热入口；历史全量归档见 `spec/CHANGES_ARCHIVE.md` |
| 接口契约定义 | 根目录 `openapi.yaml` | 后端导出并驱动前端 SDK 生成，路径只增不减 |

## 四、开发与交付纪律

1. **红线域零侵入**：判分核心、交卷幂等拦截器、认证拦截器若无当期立案授权，严禁擅自改动。
2. **先红后绿与变异自证**：新增功能必须包含集成测试或组件用例；通过 `scripts/mutation-check.sh` 注入破坏性逻辑，验证断言能够击红（Oracle 非装饰性），并完成五步原子复原。
3. **自述产物不是交付证据**：不要在汇报中仅声称“已完成/测试全绿”。验收三要素：**实际提交的 SHA + 门禁当次执行命令与原始 Tests run 输出 + 变异证据**。
4. **门禁命令**：后端以 `AGENTS.md` 指定命令为准（`./mvnw clean test`），前端运行 `lint:check`、`type-check:check`、`test`。
