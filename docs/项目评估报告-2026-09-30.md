## 3. 项目概况与优势

- **形态**：Spring Boot 3.5.5 单体（Java 17）+ 同仓库 Vue3 前端 + MySQL 主从 / Redis / RabbitMQ；业务覆盖认证、题库、考试、监考防作弊、判分、成绩、复核、补考全链路；观测栈（Prometheus 告警、Grafana、慢 SQL、DLQ 重投）与限流、分布式锁、多实例扫描安全等可靠性设施齐备。
- **过程纪律是本项目最突出的资产**：19 个能力域均有基线规格，**70 个变更归档齐全**；其中 `attribute-my-exams-list-index` 的证据件经指导 agent 复核发现解析器违背冻结 §6 等缺陷，裁决结论经独立重算成立（GO / submissions=A1 / candidates=null 不变），证据件已按返修更正（2026-09-30 第 1 笔 `69d2950`）；证据链纪律为判据测量前冻结、先红后绿、机械裁决、sha256 清单；多份性能优化以 NO-GO 如实归档而非强行实施；文档体系按「路由不做事实源」组织，根入口不承载易变事实。
- **当前质量信号**：门禁 329 用例双轮全绿（Skipped 1 为设计使然的契约导出开关）；四条硬约定自查全绿；无进行中变更；测试与实现的红绿护栏常态化入库。

## 4. 开放事项与风险（按优先级）

1. **F-B（安全面，需裁决）**：`enter()` 只调 `makeupService.assertCanEnter`（本轮 grep 实测确认该调用仍只在补考路径生效），不校验学生与考试的班级归属；列表可见性收窄后，「看不见的考试仍进得去」这一既有不一致变得显眼。`current()`/`paper` 同型。**不宜由实施 agent 自行选择**，需用户裁决：补归属校验，还是显式承认「公开考试」渠道（与 F-C 同一裁决）。
2. **F-C（产品口径）**：无班级、无名单、无答卷的已发布考试，改后对学生完全不可见（改前会出现在全局窗口）。是否需要「全校公开自选考试」第四渠道，是用户可见的行为变化，需产品确认。
3. **main 分支长期滞后，且全仓提交零异地副本（实测 279 个提交，`HEAD..main` 为 0）**：main 停在阶段 8 的缓存提交 `34bfbbd`，阶段 9 之后全部工作（含前端五阶段与全部性能优化）只在 feature 分支上。每轮评估此数字都在增长；若 main 被当作可交付基线或回滚锚点使用，风险随之放大。**风险升级（2026-09-30 返修当次实测）**：`origin=git@github.com:fzdzzj/examOnline.git` 存在且可达（BatchMode 下 rc=0），但 `git ls-remote origin` 输出为空＝远端 0 个 ref；`git branch -vv` 显示本地无任何 upstream——即全仓提交（含只存仓库外的测量原件所对应的代码状态）零异地副本，单点故障面为本机。**不得自行 push/fetch，远程操作需用户单独授权**；建议合回 main 或至少打 tag 固化当前 329 全绿稳态（同样待用户授权）。
