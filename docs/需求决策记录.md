# examOnline —— 关键场景决策记录（v1.0）

> **编制日期**：2026-09-10
> **性质**：需求规格说明书的补充，明确"同一事件不同情况"的处理策略
> **状态**：已与产品负责人逐项确认

---

## 一、交卷与时间边界

### 1.1 交卷时间冲突（倒计时归零瞬间点交卷）
- **决策**：以**服务端时间为准**。前端倒计时仅作展示，交卷时后端校验服务端时间戳；判定超时则按"超时自动交卷"处理。
- 依据：前端时间不可信（可篡改），《需求规格说明书》§5.1。

### 1.2 重复交卷（双击/网络重试）
- **决策**：**幂等处理，首次为准**。`exam_id + student_id` 唯一约束（uk_exam_student），重复交卷请求直接返回首次提交结果，不覆盖、不新增记录。

### 1.3 手动交卷后反悔
- **决策**：**不可反悔**。交卷即终稿，与"幂等首次为准"一致；学生漏题不提供撤回，可事后走成绩复核流程。

### 1.4 迟到学生剩余时间
- **决策**：**按时间窗截断**。剩余时间 = min(个人时长, 距时间窗结束剩余时间)，保证所有答卷在时间窗内结束。迟到允许分钟数由 `allow_late_minutes` 控制。

### 1.5 教师提前结束考试
- **决策**：教师点"结束" → 未交卷学生按**最后自动保存的答案强制交卷**，不另行作废、不延长作答。

## 二、断线与故障恢复

### 2.1 断网 + 本地倒计时归零
- **决策**：**本地归零即锁定**。前端本地倒计时归零后锁定答题界面并标记"待同步"，网络恢复后按锁定状态提交；服务端仍以服务端时间兜底校验。

### 2.2 浏览器崩溃 / 误刷新
- **决策**：**自动保存续考**。30 秒自动保存 + 崩溃前最后状态落本地，重新进入恢复最后保存的答案，个人倒计时按已消耗时间继续（不暂停）。

### 2.3 服务器宕机恢复（自定义补充）
- **决策**：**自动保存续考 + 补偿时间 + 前端本地缓存配合**：
  1. 前端本地（IndexedDB）持续缓存待同步答案，宕机期间作答不丢失；
  2. 服务恢复后前端自动同步本地缓存，更新自动保存；
  3. 为受影响学生**延长等量时间**（宕机 10 分钟补 10 分钟），由后端记录宕机时间窗并统一顺延个人截止时间。

### 2.4 离线答案冲突（多设备/多端同步）
- **决策**：沿用 §5.1 规避方案——`version` 版本号 + 时间戳，**以最新版本为准**，冲突时丢弃旧版本并记录日志。

## 三、防作弊

### 3.1 切屏检测达到阈值
- **决策**：**只警告 + 记录，不强制交卷**。切屏事件全部落 `exam_behavior_logs`，前端弹警告；是否作废答卷由教师事后依据行为日志判定。
- 说明：文档 §7.3"强制交卷"**不启用**，避免误伤。

### 3.2 多设备登录进入考试
- **决策**：**踢掉旧会话**。新设备进入考试后旧设备会话立即失效（Redis 会话强制下线），防止一账号双端作答。

### 3.3 人脸识别失败 / 无摄像头
- **决策**：**教师人工放行（实时审批 + 无人时降级存档）**：
  1. 优先走教师后台实时审批；
  2. 考试进行中教师不在线时，自动降级为**拍照存档**进入考试，考后由教师抽检复核；
  3. 不采用"识别失败禁止进入"的严格模式。

### 3.4 随机抽题 / 选项乱序的稳定性
- **决策**：**进入时锁定一次**。进入考试时抽题 + 乱序并锁定，刷新、断线重进均不重新抽取，防止"刷新刷题"。

## 四、考试中试卷变更

### 4.1 考试进行中教师修改试卷
- **决策**：**锁定试卷，禁止修改**。考试开始后试卷冻结（改题/删题/改分值均不允许）；修改只能在考试结束后进行，且只影响后续场次。
- 延伸：考试结束前若发现题目有误，走 §5.2 错题补偿流程。

## 五、成绩管理

### 5.1 补考/缓考成绩规则
- **决策**：**按考试配置，提供规则选项**：教师发布补考/缓考时选择该场次的成绩规则——
  - 取最高分
  - 取最近一次
  - 取平均分
- 所有历史成绩记录保留，不覆盖删除。

### 5.2 客观题答案有误的补偿（发布后）
- **决策**：**修正答案重新判分**。流程：撤回已发布成绩 → 教师修正标准答案 → 重新判分（客观题全量重算）→ 重新发布。与该题相关的学生成绩以新判分为准。
- 备选方案（未选）：废题全员加分、人工逐个处理。

### 5.3 成绩发布后撤回
- **决策**：**撤回后学生端隐藏成绩**，状态回到"已批改"，学生端显示"成绩待发布"；所有撤回操作留审计日志（谁/何时/原因），撤回需管理员权限。

### 5.4 成绩复核期间学生端显示
- **决策**：**复核中隐藏成绩**。学生提交复核申请后，其成绩在学生端锁定隐藏、显示"复核中"；复核完成（重新批改/调整分数）后更新显示。防止"看了分数再申请"。

## 六、技术实现要点（由上述决策推导）

| 决策 | 实现要点 |
|---|---|
| 服务端时间为准 | 交卷/超时校验一律用后端时钟；Redis 记录开始时间戳 |
| 幂等交卷 | `uk_exam_student` 唯一索引；重复请求返回首次结果（200 + 已存在标记） |
| 本地归零锁定 | Service Worker + IndexedDB 本地状态机：作答中 → 已锁定待同步 → 已同步 |
| 宕机补偿 | 后端记录宕机窗口 → 受影响学生个人截止时间统一顺延；前端本地缓存全量答案 |
| 踢旧会话 | Redis 会话表存 `session_id`，新会话进入时使旧 session 失效 |
| 人脸降级 | 审批接口 + 自动降级开关；降级记录单独标记，考后抽检队列 |
| 锁定抽题 | 进入考试时生成 `exam_paper_snapshot`（快照表），后续一律读快照 |
| 错题修正重判 | 判分引擎支持"按题目重算"：撤回发布 → 改答案 → 重跑客观题判分 → 重发布 |
| 复核隐藏 | `exam_submissions.status` 增加"复核中"状态；学生端按状态过滤显示 |

## 七、第三轮决策（2026-09-10 补充）

### 7.1 宕机补偿范围
- **决策**：仅补偿**正在作答中**的学生（已点"开始考试"且未交卷），未进入者不受影响。

### 7.2 错题修正重判范围
- **决策**：**仅客观题全量重算**，主观题教师批改结果不动。

### 7.3 踢旧会话确认
- **决策**：新设备弹"检测到已有会话，是否接管？"**确认弹窗**，确认后旧会话失效；防误触。

### 7.4 填空题判分
- **决策**：**归一化精确匹配**。答案去首尾空格、全半角统一、大小写不敏感后精确匹配；多空分别判分，各空分值均分。

### 7.5 主观题批改未完成
- **决策**：**允许发布 + 整体标记"部分批改"**。未批题目按 0 分计入总分，学生端可见"部分批改"标记，学生可走成绩复核。

### 7.6 监控中处置作弊
- **决策**：教师可**强制交卷 + 标记"异常待查"**。该答卷成绩暂不发布，查证后由教师定夺（正常/扣分/作废）。

### 7.7 删除考试
- **决策**：**软删除 + 状态限制**。未开始可删；已发布/已结束必须先撤回或归档；历史答卷保留（is_deleted）。

### 7.8 考后即时解析
- **决策**：**默认延迟发布，按考试可配置**。默认成绩发布后学生才可见错题解析，防答案泄露给未考学生。

### 7.9 开始计时方式
- **决策**：**点击"开始考试"才计时**。学生经过考前核验/说明页点击开始后启动个人倒计时；仅进入考试列表不计时。

### 7.10 答卷回看权限
- **决策**：**成绩发布后**学生可回看自己的试卷、答案与每题解析。

## 八、第四轮决策（2026-09-10 补充）

### 8.1 客观题即时出分
- **决策**：**按考试配置**。发布考试时教师选择"交卷即显示客观题分"或"全部批改后统一出分"。

### 8.2 补考对象确定（自定义）
- **决策**：**教师按分数筛选后指定**。教师可先按成绩条件筛选学生（如低于某分数线/缺考/未交卷），再勾选指定进入补考名单。

### 8.3 选做题计分
- **决策**：**选做答对加分**。选做题不计入必答总分，学生选做且答对额外加分；需防止总分超过满分（超满分按满分封顶，或按考试配置处理）。

### 8.4 成绩导出内容
- **决策**：四种导出全做：**全班成绩单、逐题得分明细、题目统计表（答对率/难度/区分度）、个人成绩单**。

### 8.5 错题本归集范围
- **决策**：**全部考试类型**（正式考试+随堂测验+练习）的错题都归集，支持按考试类型过滤。

### 8.6 学生账号来源
- **决策**：**管理员 Excel 导入 + 初始密码**，预留教务同步接口。

### 8.7 教师权限边界
- **决策**：**仅本人课程/班级 + 管理员授权**。跨班级查看/批改需管理员显式授权。

### 8.8 通知渠道
- **决策**：**站内信 + 微信模板消息**双通道。

### 8.9 多选题判分
- **决策**：**漏选给部分分、错选/多选 0 分**；部分分比例按考试配置。
- **实现注记（2026-09-10）**：部分分系数"按考试配置"需 exams 表加字段，属考场次结构变更。阶段 6（add-grading-score）首版采用**全局默认系数 1.0**，不改 exams 表；场次粒度配置作为后续变更 `add-partial-score-config` 单独落地。

### 8.10 缺考定义
- **决策**：**时间窗结束仍未点击开始 = 缺考**，记录缺考状态；缺考学生可被教师筛选后指定补考。

## 九、第五轮决策（2026-09-10 补充）

### 9.1 人脸识别频率（重要分歧点，见 §9.11）
- **决策**：**仅考前核验一次**，考中不抽拍。隐私友好、体验好，但防替考能力弱于文档 §5.2 的"每 5 分钟+异常抽拍"方案。

### 9.2 设备/IP 限制
- **决策**：**记录 + 报警不阻止**。记录设备指纹/IP 展示给教师，异常时报警（行为日志高严重度），但不硬性阻止/不强制交卷。

### 9.3 浏览器锁定强度
- **决策**：**全屏 + 禁用复制/右键**。不拦截开发者工具（易误伤且可绕过）。

### 9.4 行为日志可见性
- **决策**：**仅教师可见**。教师端可按事件类型/严重度筛选，查看全班行为时间线；学生不可见。

### 9.5 排行榜与隐私
- **决策**：**默认关闭**，教师发布时可开启；开启时仅**匿名显示前 10 名**。

### 9.6 口语题流程
- **决策**：录音上传 → 自动转文字 + AI 初评 → 教师复评确认；无 AI 能力时降级为纯人工听评。

### 9.7 代码题判分
- **决策**：**隐藏用例全判**。教师配置输入/输出/时间限制，正式测试用例对学生隐藏，防调试刷分；仅展示示例用例。

### 9.8 判分异常处理
- **决策**：判分失败（沙箱超时/解析失败/数据损坏）标记"**判分失败**"，教师可重判或手动给分，不影响其他学生。

### 9.9 消息通知时机
- **决策**：四类通知全做：**考前提醒**（提前 N 分钟，默认 30）、**成绩发布提醒**、**缺考/异常通知教师**、**流程性通知**（补考名单确定/复核结果）。渠道：站内信 + 微信模板消息。

### 9.10 成绩可见性
- **决策**：**学生仅见自己成绩**；教师可见全班并可导出。不做全班匿名可见。

### 9.11 待确认：人脸策略取舍
- 选"仅考前一次"意味着考中换人无法被系统发现。请确认接受此取舍，或改用折中方案：
  - **方案 A（已选）**：仅考前核验，考中零抽拍 —— 隐私最好，防替考靠自觉/现场监考；
  - **方案 B（折中）**：考前核验 + 考中低频抽拍（如每 15-20 分钟 1 次，可配置），异常行为触发即时抽拍；
  - **方案 C（文档原案）**：每 5 分钟 + 异常即时，威慑最强。
- 若维持 A，建议保留"抽拍"接口能力，后续可平滑开启。

## 十、第六轮决策（2026-09-10 补充）

### 10.1 人脸策略取舍（终定）
- **决策**：**维持"仅考前核验"**，考中零抽拍；保留抽拍接口能力，后续可平滑开启。防替考靠自觉 + 现场监考 + 设备/IP 报警。

### 10.2 离线模式范围
- **决策**：**教师按考试配置**（发布时勾选"允许离线"，默认允许）；离线答案落 IndexedDB，恢复后同步（版本号+时间戳）。

### 10.3 监考大屏内容
- **决策**：在线/离线/已交卷人数、答题进度、异常高亮（切屏/设备变化/人脸异常），点击查看学生行为时间线。

### 10.4 草稿纸（画板）
- **决策**：内置 Canvas 画板，手写演算保存为图片**附在答卷中**，教师批改/争议时可查看。

### 10.5 微信扫码登录
- **决策**：**首次扫码自动创建账号并绑定**，后续扫码即登录；需校验实名信息一致性。

### 10.6 账号安全
- **决策**：连续 5 次密码错误**锁定 15 分钟** + 找回密码（邮箱/管理员重置）。

### 10.7 成绩复核限制
- **决策**：每场考试**限申请 1 次**，成绩发布后 **7 天内**可申请，超期不可。

### 10.8 A/B 卷
- **决策**：**延后到 V2**。MVP 先做选项乱序 + 随机抽题，A/B 卷分配机制（进入时随机锁定）V2 实现。

### 10.9 题目查重
- **决策**：录入/导入时相似度比对，命中标记"**疑似重复**"由教师人工确认，不自动拒绝。

### 10.10 试卷快照
- **决策**：**考试发布时生成试卷快照**；答卷、判分、回看一律读快照，之后改题不影响已考场次。

## 十一、第七轮决策（2026-09-10 补充）

### 11.1 题目分值覆盖
- **决策**：**试卷内覆盖**（paper_questions.score 覆盖题库默认分），改试卷内分值不影响题库默认值，互不干扰。

### 11.2 试卷模板版本
- **决策**：**版本管理 + 回滚**。模板每次修改生成新版本，可查看历史并回滚；已发布考试绑定具体版本（配合快照）。

### 11.3 蓝图组卷
- **决策**：**MVP 即做**。教师填知识点×难度矩阵，系统按比例抽题，超出题库容量时提示教师调整。

### 11.4 标签结构
- **决策**：**扁平标签多选**（学科/难度/题型/自定义），建题时可多选。

### 11.5 题目软删除
- **决策**：**软删除 + 快照隔离**。已被快照引用的题删除后历史答卷仍可查看，仅新组卷不可用。

### 11.6 成绩排名并列
- **决策**：**并列同名次**（1,2,2,4）。

### 11.7 题目质量分析时机
- **决策**：考试批改**发布后自动生成**题目统计（难度/区分度/选项分布），教师端随时可看。

### 11.8 分析报告形式
- **决策**：**Web 在线报告（图表交互）+ 一键导出 PDF** 双形式。

### 11.9 错题重练
- **决策**：**错题本内直接重练**（答题→判分→更新归集状态），连续 3 次做对自动移出。

### 11.10 练习模式
- **决策**：学生**自选题目/标签组练习卷**，不计入成绩、可看解析，与考试独立。

## 十二、第八轮决策（2026-09-10 补充）

### 12.1 考试列表组织
- **决策**：**状态分组 + 时间排序**。待考→进行中→已完成分组，组内按开始时间近→远。

### 12.2 答题导航
- **决策**：**左侧题号导航面板**，已答/未答/标记三色标识可跳转；交卷前提示未答题目数。

### 12.3 听力题播放
- **决策**：每题独立音频，**限次重播（默认 2 次，可配置）**。

### 12.4 考试工具

## 十五、事务回滚策略（2026-09-13 补充，防御性规范统一）

> 对应 spec 变更：`spec/changes/add-tx-rollback-consistency`，data-consistency 规范新增「事务回滚策略」。
> 背景：非 bug 修复。当前全部受检异常均已在业务边界 catch 并转 `BusinessException`（继承 RuntimeException），裸 `@Transactional` 当前能正确回滚；本策略用于消除对 Spring 默认回滚语义（仅 unchecked 回滚）的隐式依赖，防止未来有人直接 throws 受检异常时事务**静默提交**导致数据半提交。

- **决策**：所有 `@Transactional` **显式声明 `rollbackFor = Exception.class`**，受检异常同样触发回滚；不依赖 Spring 默认值，自文档化（读代码即知"本方法出错一定回滚"）。
- **决策**：受检异常（`JsonProcessingException`/`IOException`/`MessagingException`/`InterruptedException` 等）一律在**业务边界** catch 并转换为 `BusinessException` 重新抛出，不允许跨事务边界直接传播。
- **决策**：**禁止裸 `@Transactional`**（不带 rollbackFor）。代码审查与提交前 grep 检查 `^\s*@Transactional\s*$` 应为 0 处残留。
- 依据：Spring 事务默认仅在 RuntimeException 与 Error 时回滚，checked Exception 默认不回滚（静默提交）；显式 rollbackFor 把风险从"依赖个人自觉"变为"框架强制"。
- 落地：2026-09-13 统一 26 处裸注解为 `@Transactional(rollbackFor = Exception.class)`（9 个 Service 类），未引入传播/隔离/只读等其他属性；全量回归确认无行为变化。

## 十六、代理型增强必须验证生效（2026-09-20 补充，一批"空转交付"的复盘）

> 对应 spec 变更：`spec/changes/archive/{add-thread-pool-isolation,optimize-transaction-boundary,add-api-rate-limiting}`（三者均**部分或全部撤回**，见 proposal 顶部）。
> 背景：本轮复核发现多处"写了注解/配置但运行期根本不生效"的交付，测试全绿却零效果。共性是**只验证声明存在，不验证声明起作用**。

- **决策**：由 Spring 代理实现的增强（`@Transactional`/`@Async`/方法参数校验），必须验证其在运行期真的生效；**private 方法或同类自调用上的事务/异步注解一律视为无效声明**，要么改由外部协作者承载，要么删除注解并如实描述真实边界。
- **决策**：`@RequestParam`/`@PathVariable` 上的 `@Min`/`@Max` 必须配合**类级 `@Validated`** 才走
  `ConstraintViolationException` 这条已映射到 400 的路（不同于 `@Valid @RequestBody` 的
  `MethodArgumentNotValidException`）。三态实测见 §十九首条：无注解静默放行、有注解无 `@Validated`
  落入 500、两者齐备才是对客 400。
- **决策**：有返回值且返回值被调用方使用的方法**禁止挂 `@Async`**（`sweep()` 返回 int、`collect()` 返回 EventVerdict 两处实测抛"Invalid return type for async method"，行为上报接口全量 500）。
- **决策**：`@Async` 边界上 MDC 与 SecurityContext 均不传递——依赖它们取值（当前登录人、traceId）的逻辑不得异步化，除非显式把值随参数带过去。审计服务因此改为**同步写**。
- **决策**：线程池隔离方案整体撤回（三个池在误用注解移除后零租户、异步交卷入口零调用方）。将来有真实批量重活时，连真实调用方与"能证明隔离起作用"的并发测试一起重建，不预先占空池。
- 依据：`ThreadPoolConfigTest` 断言池参数与"三池互不相同实例"，在零租户下依旧全绿——全绿不等于能跑。
- 落地：`df5f311` 删池与 `@EnableAsync`；`5999b1e` 修 `@Async` 误用；`f740725` 后补 `@Validated` + `ConstraintViolationException` 处理，并以红→绿测试（`oversizedPageSizeIsRejected`）实证。

## 十七、指标口径两条硬规则（2026-09-20 补充）

> 对应 spec 变更：`spec/changes/archive/{add-concurrency-monitoring,optimize-transaction-boundary}`，observability 规范新增「指标基数有界」。

- **决策**：耗时类指标一律以**纳秒精度**录入（`timer.record(nanos, NANOSECONDS)`），禁止先换算成"秒"再转整型——SETNX 锁等待本是毫秒级，`(long) 0.05` 会把每次采样截成 0，导致 P95 恒 0 而"看起来极健康"，让"P95 < 100ms"这类验收**假通过**。
- **决策**：分位数有明确验收口径（如 P95 < 100ms）时，必须**显式铺覆盖该区间的分桶**；Micrometer 默认桶在 10ms 之后直接跳到 8s，落在空档里的观测值只能得到跨三个数量级的线性插值。
- **决策**：计数器/直方图标签只允许**取值集合有限**的维度（如 `status`），禁止用考试 ID 这类随业务量无上界增长的字段作 tag——时间序列数量会线性膨胀，内存与查询成本失控；个体明细回到返回值或审计表查。
- 依据：Micrometer/Prometheus 基数与桶机制；本轮实测 `Duration.ofSeconds((long) s)` 与 `exam_publish_*` 带 `exam_id` tag 两处均由人工复核发现，测试当时零覆盖。
- 落地：`BusinessMetrics.recordLockWait(long nanos)` + 1ms–1s 显式分桶；`exam_publish_*` 收敛为 `exam_publish_total{status}`；新增 3 条测试进既有 `BusinessMetricsTest`，两类变异（种回截断、摘掉分桶）各只红对应用例。

## 十九、审计读接口与参数校验三态（2026-09-20 补充，d2cbde9）

> 对应规范：authentication 新增「审计事件查询」Requirement；本条同时纠正 §十六 里一处失实归因。

- **实测（三态）**：`@RequestParam long size` 上加 `@Max(100)`，请求 `size=101`——
  1. **注解本身没有**：打到服务层被 `Math.min` 夹成 100，返回 200（静默降级）；
  2. **有 `@Max`、类上无 `@Validated`**：Spring 6.1 的**内建方法校验照样拦截**，抛
     `HandlerMethodValidationException`，未被全局异常处理器映射 → **500**；
  3. **有 `@Max` 且类上有 `@Validated`**：走 AOP 代理抛 `ConstraintViolationException`，
     已映射 → **400**。
  两个控制器（`ExamController`、`AdminController`）逐一删注解复跑，均为第 2 态的 500。
- **纠错**：§十六 原写"必须配合类级 `@Validated` **才触发**"是错的——`@Validated` 决定的是
  **对客看到 400 还是 500**，不决定校验发生与否。原句里"实测 `size=1000` 返回 200"记录的其实是
  第 1 态（注解尚未添加时），被误当成第 2 态的证据。
- **遗留（未做，非遗漏）**：`HandlerMethodValidationException` 目前仍未映射。当前代码里只有两个
  带参数约束的控制器且都挂了 `@Validated`，该异常无可达路径，故不预先加处理器；
  一旦新增"带 `@Min`/`@Max` 却不挂 `@Validated`"的控制器，就需要补这条 400 映射。
- **决策**：审计查询落在既有 `GET /api/admin/audit-logs`，不另开 `/audit/logs`——`/api/admin`
  前缀已带类级 `@RequireRole(ADMIN)`，另开路径等于再造一套鉴权。
- **决策**：该接口**不挂** `@RequirePermission`。审计是 ADMIN 独有的全局视图，类级角色校验已是
  不可放宽的门槛；再补一个只能归属 ADMIN 的 `audit:read` 权限点，是把同一道门建两遍，
  并多一处 `RolePermissionInitializer` 漏配即静默失效的初始化数据。
- **决策**：分页接口对外返回**页内 List**，不返回 MyBatis-Plus 的 `Page` 信封——
  `searchCount`/`orders`/`optimizeCountSql` 等内部字段不该进对外契约；此口径与
  `ExamController.page`、`PaperController.page` 一致（全仓库无一例外）。
- **决策**：排序方向为对外契约的一部分，须有测试钉住：只断言"返回了 3 条"在正序实现下照样绿，
  故补 id 严格倒序断言。变异验证：`orderByDesc` 改 `orderByAsc` 该用例转红。
- 落地：`AuditLogService.page` + `AuditLogResponse`（只读投影，暴露 `traceId` 供跳查 Jaeger）；
  `AdminAuditLogIntegrationTest` 4 例；`IntegrationTestBase.loginToken` 由 private 放宽到 protected。
  全量 273 tests / 0 失败（269 + 4），行覆盖 89.8%（新 DTO 的 Lombok 生成方法拉低 0.3pp，分支持平）。

## 二十、SQL 改写必须先有执行计划，且"计划类改动测试守不住"（2026-09-21 补充）

> 对应 spec 变更：`spec/changes/archive/optimize-sql-performance`（其第三条主张由"未测量"改为"已实测、不采纳"）。

- **实测环境**：独立 scratch 库 `exam_bench`（`CREATE TABLE ... LIKE` 取真实 DDL 与索引，
  10 万答卷 / 500 场考试 / `paper_json` 填 4KB 贴近真实行宽，`ANALYZE TABLE` 后 `EXPLAIN ANALYZE`），
  主库容器 `exam-mysql-master` 在 **13316**。**不改 `exam_online`，测完 DROP DATABASE。**
- **决策**：性能类 SQL 改写**必须先有执行计划与数据量**再动手。本次三行结论都只能从测量得来：
  提案主张的 `OR → UNION ALL` 在每个测点上都不更快、多数慢 2–17 倍（派生表要物化全部命中行
  才套得上 `LIMIT`，恰好摧毁了原查询"沿索引边扫边在凑满 LIMIT 时提前停止"这条赖以便宜性质）；
  原式不写互斥守卫还会多返回 36% 重复行（6000 vs 真值 4400），而其兜底 `DISTINCT` 需在两张
  longtext 上去重，实测 38.5ms。
- **决策**："`OR` 导致索引失效"要区分**索引没被选中**与**索引第二列用不上**。本例是后者
  （`key_len=1` 而非 6），真正的退化来自**优化器翻了驱动表**（改扫 exams 全表逐场回表）。
  诊断口径：看 `EXPLAIN` 的 `table` 顺序 + `EXPLAIN ANALYZE` 每节点的 `rows`/`loops`。
- **决策**：跨 MySQL/H2 的索引提示一律用**优化器提示注释** `/*+ JOIN_INDEX(t idx) */`，
  **禁用 `FORCE INDEX`**——H2（`MODE=MySQL`）不认 `FORCE INDEX`，直接语法报错
  （`MultiInstanceSweepSafetyTest` 4/4 error 实测）；注释形态 H2 忽略、MySQL 8 读取。
  且提示**不要带查询块限定符**：`JOIN_INDEX(s@select_1 idx)` 被 MySQL **静默忽略**，
  耗时与不加完全一致——这类"写了不生效且不报错"的形态与本文件 §十六 是同一类故障。
- **决策**：不为超出容量模型的形态新增索引。`(exam_id, status)` 能把 25k 进行中（>5000 并发
  包络）下的 42ms 降到 10ms，但收益点全在包络之外，代价是交卷热写路径多一份永久写放大。
- **决策**：**"计划类改动没有测试可守"必须在提交与 Javadoc 里写明**，并留下可复算的判别式
  （本例：裸查询 ~40ms / 提示生效 ~2ms）。测试跑在 H2，对该提示是哑的——
  全绿不能证明它还在起作用，MySQL 一改索引名它就静默退回慢计划。
- 落地：`selectForceSubmitCandidates` 加提示；常态忙轮 41–50ms → **1.7–2.7ms**，
  空闲轮（25k 进行中、零命中）312–366ms → 159–169ms。全量 273 tests / 0 失败。
