## 4. 关键技术决策与理由

| 决策 | 为什么 |
|---|---|
| **父 POM `dependencyManagement` 锁版本** | 版本集中一处管理（mybatis-plus 3.5.9 / jjwt 0.11.5 / jbcrypt / mysql-connector），依赖引入不写版本，杜绝冲突；与 Spring Boot 3.5.5 兼容矩阵对齐 |
| **统一响应 `ApiResponse`，成功码 `code:0, message:"ok"`** | 前后端契约唯一；前端只认 `code` 分支，不关心 HTTP 状态细节（规范场景明确要求此结构） |
| **错误码枚举带 `httpStatus`** | 业务码（如 1001）与 HTTP 状态（401/403/423/429）解耦：业务码给前端逻辑，HTTP 状态给语义/网关 |
| **全局异常处理器** | 所有异常（业务/参数校验/唯一约束/兜底）统一转 `ApiResponse`，**只记日志不向客户端泄堆栈** |
| **RequestId 过滤器** | 每个请求生成/透传 `X-Request-Id` 写入 MDC，日志格式带 `[%X{requestId}]`，出问题可全链路串联定位（面试点：可观测性） |
| **RBAC 五表 + `username` 唯一** | 支持"学生=学号、教师=工号"登录；角色表带 `level`（ADMIN 3 > TEACHER 2 > STUDENT 1），为后续角色层级授权铺路；`user_roles`/`role_permissions` 多对多关联 + 外键 |
| **逻辑删除 `is_deleted`** | 全局配置 MyBatis-Plus 逻辑删除，历史数据不物理删（考试系统历史答卷必须可追溯） |
| **建表幂等 + H2/MySQL 双兼容** | `CREATE TABLE IF NOT EXISTS`：MySQL 8 与测试用 H2(MySQL 模式) 同一份 `schema.sql`；测试环境不依赖真实 MySQL |
| **Compose 主从用 GTID 复制** | `MASTER_AUTO_POSITION=1` 免去手工指定 binlog 文件名/位置（传统方式极易配错），从库自动追平 |
| **`depends_on: condition: service_healthy`** | 从库**等主库健康检查通过**才启动，杜绝"从库先起连不上主库"；每个容器带 `healthcheck`（mysqladmin ping / redis-cli ping / rabbitmq-diagnostics） |
| **复制账号用 `mysql_native_password`** | MySQL 8 默认 `caching_sha2_password` 在无 TLS 复制连接上报 "Authentication requires secure connection"，改 native_password 解决（踩坑记录见 §6） |
| **dev/test 禁用 mail 健康检查** | SMTP 未配置时 `mail` 健康指示器会连 localhost:25 导致 `/actuator/health` 恒 DOWN；dev/test 关闭，prod 保持启用（SMTP 为生产必需） |
| **多环境 dev/prod + 环境变量注入** | 敏感信息（DB 密码/JWT secret/SMTP）不落库，`${VAR:default}` 模式，prod 无默认值强制注入 |

## 6. 踩坑记录（下次直接避雷）

| 坑 | 现象 | 解决 |
|---|---|---|
| 本环境 Maven 仓库在沙箱外不可写 | `mvn` 报 AccessDenied | 本地仓库镜像到工作区 `.m2-repo`，用 `MAVEN_OPTS=-Dmaven.repo.local=...`（settings.xml 的 localRepository 优先于 `-D` 参数，但 MAVEN_OPTS 的 JVM 属性可覆盖） |
| Mockito 5 默认 inline mock maker | 测试报 `Could not initialize plugin MockMaker` | 测试用不到 mock，加 `mockito-extensions/org.mockito.plugins.MockMaker` 文件切到 `mock-maker-subclass`（inline 需 JVM agent attach，被沙箱拦） |
| mail 健康检查拖垮 health | `/actuator/health` 返回 503 | dev/test 配置 `management.health.mail.enabled: false` |
| roles/permissions 表缺 `created_time` | 启动报 `Column "created_time" not found` | 实体有 `@TableField(fill)`，表结构必须对齐（先建表脚本再实体，二者同步） |
| docker.io 拉镜像超时 | compose up 报 registry 连接失败 | 用国内镜像源（daocloud）拉取后重打标准标签；compose 文件保持标准镜像名 |
| 本机 3306/6379 被本地服务占用 | 端口绑定冲突 | 停止本地 MySQL80/Redis 服务（数据不动），compose 容器即开发中间件 |
| MySQL 8 复制认证失败 | 从库 `Slave_IO_Running: Connecting`，`Last_IO_Error: Authentication requires secure connection` | 复制账号改 `mysql_native_password`（init 脚本已修正；如已建卷需 `ALTER USER` 修复或 `down -v` 重建） |

## 7. 当前状态与常用命令

**当前状态**：compose 栈 4 容器全部 healthy 运行中；本机原生 MySQL80/Redis 服务已停止（端口被容器占用）。

```bash
docker compose ps                 # 查看容器健康状态
docker compose logs -f <服务名>    # 看日志（如 mysql-slave）
docker compose down               # 停栈（保留数据卷）
docker compose down -v            # 停栈并清空数据卷（回到首次启动语义）
docker compose up -d              # 再启动

# 回到本机原生服务（需先停 compose）
docker compose down
Start-Service MySQL80,Redis

# 构建 / 测试 / 启动应用
mvn clean install
mvn spring-boot:run               # dev 默认连 127.0.0.1:3306 / 6379（即 compose 中间件）
```

> 注：本机沙箱环境构建需 `MAVEN_OPTS=-Dmaven.repo.local=D:\code\examOnline\.m2-repo`；正常开发机直接 `mvn` 即可。
